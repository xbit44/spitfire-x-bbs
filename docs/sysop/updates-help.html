Update SFX and solve problems

Install a matching update, repair program files and keep your board data.

Manual beta updates

Beta updates are manual. Use the matching Windows or Linux download supplied with the release and read its notes. SFX does not check for or install application updates automatically. Check the supplied archive SHA-256 before using it.

Keep a usable backup of the stopped board before an update. Read backup and verification. Keep any required backup companions together. Program repair, Core Restore and restoring missing file contents are different operations.

Linux uses a single .tar.gz download. For an existing lowercase board, follow Upgrade an existing lowercase board. Use the installed stop-management command and the new package's installer with --upgrade; closing the browser alone does not close management.

Windows: update or repair

  1. Read the new release notes. Extract the matching Windows package to a separate staging folder. These test programs are unsigned; use the supplied checksum and trusted source to identify the package.
  2. Stop the BBS and let callers and active work finish. Close Control Panel, SFXConfig and File Manager. In Service mode, stop the BBS service through the existing controls first; closing Control Panel alone leaves that service running.
  3. Run the new SFX-BBS-Setup.exe normally. Choose your existing SFX installation folder. A new empty folder is a fresh installation, not an update of your board. For an update, keep Remove SFX programs (keep BBS data and backups) and Also permanently remove the entire BBS folder unchecked.
  4. Choose Review / Continue. Review the existing-folder maintenance plan and the backup choice. Setup offers to create and verify a mutable-board-data backup in Backup\Upgrades. Choose it unless you are relying on another usable backup. The review describes what Setup will create and verify; wait for the final result before treating the new backup as verified. Setup's protected program recovery is separate and remains mandatory; it is not a full-system snapshot.
  5. Follow the actual result. Normal maintenance updates or repairs the recognized program files while retaining board data, settings, credentials and hosting mode. Do not delete retained work or repeatedly run Setup if it reports an incomplete recovery. Keep the reported paths and diagnostic.
  6. Open the installed controls, check the version and read any preparation or recovery request. Review settings before starting callers. Setup maintenance leaves the BBS stopped; start it deliberately when ready.

While Checking installation... is shown, the moving mark and Checking time report activity and elapsed checking time. Choosing Close requests a stop; Setup waits for the current read to finish before closing.

During installation, read the named stage and its file or byte counts. Those counts apply to that stage. Total since confirmation shows elapsed time since you confirmed the plan. Wait for the final result. If you did not select a shortcut, the completion message gives the installed Control Panel path.

Use matching Setup repair when a missing or unverified installed component directs you there. Repair is not a way to replace your caller database or undo a saved setting. Windows asks for administrator approval only for protected installation steps. Check a refused result rather than changing permissions or copying an arbitrary executable over the installation.

Windows: remove programs or the whole board

Choose the entry for the intended board in Windows' app-removal list, or open Uninstall Spitfire-X BBS.lnk in that installation's folder. Depending on Windows, the app list is called Installed Apps, Apps & features or Programs and Features. These routes use Setup's engine; check the exact selected installation folder before continuing.

The default is Remove SFX programs (keep BBS data and backups). It removes that selected installation's recognized programs and related selected-installation registration/shortcuts while retaining its board data and backups. Other boards and shared dependencies are not selected by this choice. Use the normal stop/close controls first and follow any busy or verification refusal; do not force removal around active work.

Also permanently remove the entire BBS folder is a separate, initially unchecked choice with an explicit selected-folder confirmation. It can remove the board's data, backups and custom content as well as programs. Review a usable separate backup and the exact folder before confirming. A checkbox or started operation is not proof that removal completed; read the final result.

Fresh install again at the same path

Default program removal leaves an existing, nonempty board folder. For a fresh board at that same path, finish removal and close the installation, move the entire retained folder aside intact, then reopen matching Setup for the original path. Do not delete a few settings or merge old/new fragments to make a retained board appear fresh. To keep using the original board, use update/repair instead of a fresh installation.

Missing or deleted installation folder

Missing-folder recovery asks you to confirm that the folder was intentionally deleted and that its original volume is present. Confirm only when those conditions are true. A moved/renamed board, offline drive, access failure or possible restored copy is not evidence of intentional deletion. Keep its data and registration for review, rather than removing records merely because one path is unavailable.

Windows: moved, copied or restored board

Keep the complete board together and read the reported folder/path diagnostic. When SFX offers Prepare, its dialog identifies the exact folder and describes local access/registration after the move, copy or restore. Review that folder and the proposed action before continuing. Use the reported preparation/recovery route, with matching Setup repair where directed; do not hand-edit registrations or discard identity/data files to bypass a refusal.

Preparation is not the new-board First-Run Setup and is not a general repair for every verification, IPC or configuration-read failure. Preserve uncertain or incomplete work and the original diagnostic. Other boards and shared dependencies remain outside the selected installation's action.

If Windows 10 or 11 reports a ClamAV receipt problem after Prepare SFX, use the prepared-board ClamAV repair steps. Check the exact folder, then verify both the scanner and its definitions before relying on upload scans.

Check the release version

This test release is 1.0.0b2 on both Windows and Linux. Check About or the displayed program version against the package notes. SFX keeps one shared release version, even when a change affects only one platform or a file such as FILE_ID.DIZ. Matching version numbers do not mean identical platform changes.

The root README.txt on Windows or readme.txt on Linux is the short starting guide. Keep the corresponding help folders with the installation: Windows uses Docs/Sysop, Docs/Doors and Docs/ThirdParty; Linux uses docs/sysop, docs/doors and docs/thirdparty. The Wiki can be read and searched offline. Complete helper source and other source companions are separate from the small runtime download; use the matching source-availability list supplied with that release.

FolderWhat to read there
Windows: Docs/Sysop; Linux: docs/sysopThis offline Wiki and its search files.
Windows: Docs/Doors; Linux: docs/doorsSupplied Door guides, licenses and notices. Door programs and configuration stay in their program folders under Doors on Windows or doors on Linux.
Windows: Docs/ThirdParty; Linux: docs/thirdpartySFX license, software credits, original component notices and source information.

A normal update can add missing default guides without moving your Door programs, replacing their configuration or deleting old custom documentation. Keep a copy of guides you have edited.

Windows Setup keeps internal stock-document records to recognize files it may refresh. Leave these records in place, including an older tracking file you may find under Docs. Use normal Setup update or repair; do not delete tracking files to force a refresh. Keep a separate copy of your own edited documentation.

Find a problem

On Windows, a Control Panel that is still starting is not proof that callers or FTN mail can connect. Read Windows startup, then check the actual BBS and listener status. Keep the startup diagnostic if required checks fail.

Start with the result shown by Setup or the page you used. If callers cannot connect, check whether the BBS and the intended Telnet/SSH listener are running and whether the configured address and port are available. If a setting was saved but is not active, read Applied, Pending or Restart required before saving it again.

Read Events, Live Logs and the matching files in the board's Logs folder on Windows or logs folder on Linux. Windows uses SFXRuntime.log/HEYSYSOP.LOG; Linux uses sfxruntime.log/heysysop.log for operating events/Sysop attention. For stopped-board checks and retained recovery work, use BBS Health Check. It reports findings and next steps; it does not repair or clear them.

If a save or operation has an unknown outcome, use its offered status/review action first. Preserve failed or uncertain work and the original diagnostic. Do not assume that closing a window cancelled a running operation.

Localhost, ports and SyncTERM

For a caller test on the BBS computer, set the terminal entry's host to 127.0.0.1 and select the correct protocol and saved caller port. Fresh examples are Telnet 2323 and SFX SSH 2222; an existing board may use different values. These are not browser-management or operating-system SSH ports.

If localhost fails, an IPv6 resolution can differ from SFX's configured IPv4 listener. Try the explicit IPv4 address before changing unrelated settings. Check BBS/listener status and read the reported bind or startup error. From another computer, use the BBS computer's reachable IPv4 address instead of that client's loopback address. See the complete caller connection examples.

Report a problem

When asking for help, include your SFX version and Windows or Linux version, what you did, what you expected and what happened. A useful log message or screenshot helps. Leave out passwords and private information.
