Add and maintain Doors

Register a program or remote BBS, set its requirements, then choose where callers see it.

A Door definition holds shared program and access settings. A menu entry places that Door on a menu, with its own number, displayed name and description. The same Door can appear in several places. Changing its shared settings affects all those placements.

Linux Doors controls

This section describes the Linux 1.0.0b2 Door controls. Earlier beta.8 packages keep their previous controls.

In Linux SFXConfig, open Doors. In the wide Door Menu tree, select the category where callers should find the Door. The selected-item summary and actions are below the tree. Choose Add Door, then DOS game, Linux program, Remote BBS — Telnet or Remote BBS — RLogin. The category stays with this setup. Review the settings and caller menu number, title and description, then choose Save and add to the named category. Saving does not install or run a program; its files must already be on the Linux BBS computer.

Select an existing Door before Edit Door. Shared settings apply everywhere that Door appears; changing a menu entry's name or number changes only that placement. More Actions keeps the existing add/reuse, duplicate, move, ordering and removal tasks available. Add Unplaced / Event Door saves a configured Door without forcing it onto a caller menu. All Configured Doors includes items not on a menu. Check the selected item and the removal preview before deleting shared settings. Program files are kept.

Use Save Changes for the current editor. Discard Changes drops its unsaved edits; it does not undo an earlier save. When leaving an unsaved editor, choose Save, Discard or Stay, subject to the actual operation state. After an uncertain creation save, use Check Save Result before another write. A new remote password or pepper is cleared rather than stored in the browser draft.

For an uncertain remote-BBS creation, Check Save Result can show the current name, code, command, access settings and whether protected credentials are present. It cannot read back the password or pepper you submitted. Presence alone does not confirm that value. The pending save stays locked if its exact result cannot be confirmed; SFX does not repeat the save or the credential. Keep the result for review without including secrets. This is a current recovery limit.

Door creation and menu placement save separately. If the Door is saved but placement fails, keep that Door and correct its placement; do not create another copy. If a reply is missing, review the exact saved result first. A confirmed save followed by a failed list refresh is different from an unknown save outcome: the change saved, but the updated view could not be read. Follow the specific result shown.

DOS Runtime Setup checks/reuses or prepares and saves the emulator choice without adding a game. For a complete game, use Add Door > DOS game; see Guided Linux DOS setup. The Other Door tools section at the bottom includes DOS Runtime Setup…, Door Bulletins… and All Configured Doors…, with Help for Doors there too.

Guided Linux DOS setup

On Linux, select the wanted category, choose Add Door > DOS game and follow the six steps. The separate Doors > DOS Runtime Setup uses only the runtime check/preparation/save step; after DOS runtime saved, close it to return to Doors. It creates no Door or menu entry. The earlier beta.8 ZIP has the Doors > Set up DOS doors wizard; beta.7 ZIPs do not contain that wizard. Stop the BBS first and leave browser controls open.

  1. Check DOS support. Choose the actual installed AMD64 DOSEMU2 executable and check its required DOS resources. Use the optional runtime-prefix field for an extracted copy. Save the checked choice for later games. Recheck it after replacing or updating that executable.
  2. Choose a game. Enter an existing game folder, find its DOS programs and enter the command and arguments from its instructions. Folder paths currently cannot contain spaces, quotes, backslashes or links. SFX does not download games or run their installers.
  3. Connect the caller. Choose the game's I/O method and drop file. SFX asks instead of guessing. Leave Input pacing (ms) at 0 for no added delay, or select a delay for a DOS serial game that misses fast input. Set minimum security and simultaneous-caller support. New games start Sysop-only for testing unless you change that choice.
  4. Choose the menu. In the pilot, the category chosen before Add Door is preselected. Review it and choose an unused number. Existing menu entries are kept.
  5. Review and save. Review the per-game CanDisconnect=false requirement, selected input pacing, Door settings and placement. Other valid driver settings are preserved. Finish with Save and add to the named category. A saved Door remains available if placement needs correction; use Place Saved Door to finish that stage. Use Refresh / Review Saved Result after an uncertain response; the wizard never automatically repeats a save.
  6. Test as a caller. Start the BBS and enter the game through a normal Sysop session. Check the caller/node, normal typing, fast or pasted input, scores and return to SFX. Test caller disconnect, time limits and a Sysop stop. If simultaneous callers are enabled, keep two different callers inside the same game together and check a shared action. Test each caller connection you offer, such as SSH and Telnet. Then use Edit Door to change access as needed.

The installed-runtime check does not require a named distribution. Automatic preparation of a separate SFX copy currently uses the qualified Pop!_OS 22.04 AMD64 profile. Other systems use their distribution's DOSEMU2 installation instructions, then check the installed runtime here. SFX does not run sudo, change repositories or install system packages.

Preparation shows activity and has its own cancellation action. Closing with edits offers the allowed Save, Discard, Stay or Close / Keep Draft choices. An incomplete setup cannot be saved as a finished Door; an uncertain operation must be reviewed before another save. Discarding draft text does not undo saved runtime, game-driver or Door settings, and closing does not cancel background preparation. Saved DOS support remains available for another game. A runtime check or saved configuration does not mark the game tested.

For manual preparation, the Linux package also installs bin/tools/prepare_linux_dos.py and its matching linux_dos_pop22_amd64.json profile together. Keep both files in that folder; the helper reads the profile beside itself. See docs/linux_dos_doors.txt for the command and profile limits.

Input pacing for an older DOS game

Input pacing (ms) accepts a whole number from 0 to 100. The default is 0, which adds no delay. For original OGSF Guess, earlier adapter checks used 75 ms when rapid input lost digits. Choose it for that game only when needed; SFX does not enable it for every Door. The delay affects characters sent to a DOS UART/FOSSIL serial reader. Screen output, Native Doors and DOS standard input/output are unaffected.

The wizard saves the choice as DosInputIntervalMs in the [SFXEXEC] section of the game's sfxexec.ini; for example, DosInputIntervalMs=75. With no saved pacing setting, the default is 0. Rechecking a game keeps its saved choice unless you change it; enter 0 to turn pacing off. SFX refuses invalid or out-of-range values when saving or launching, so correct the value before trying again. Other driver settings are preserved. Windows accepts this key in a copied configuration but does not apply this Linux setting.

After changing pacing, check that complete numbers and commands reach the game through your actual caller connection. A successful save or one correctly typed character does not establish that fast input works. The current Linux package includes this saved wizard option; earlier beta.7 ZIPs do not.

Installed development checks

November 15 checks on native Pop!_OS 22.04 and Linux Mint 22.3 used the new wizard/backend and actual installed BBS caller routes. Original OGSF Guess passed SSH and Telnet checks with saved 75 ms pacing: complete rapid number input, a winning score and clean return. Usurper 0.25 passed SSH and Telnet checks using FOSSIL, DOOR.SYS and pacing 0. It confirmed a 500-gold deposit, wrote scores and saved the character; the persistent numeric bank balance was not independently decoded. Guess/Telnet caller-disconnect and Sysop-stop checks also passed on both systems.

On each system, two different SSH/Telnet callers also played in one shared Usurper game. Game nodes 1 and 2 matched SFX and their separate private drop files. The first player saw the second player's name in both entry and departure notices, and stayed in the game while the second returned to the BBS. The second player's launch files were removed while the first player's remained active. Both wrote scores and returned cleanly, and the same game data contained both characters. In-game mail was not qualified.

Both BBS hosts stopped with no callers, and original game executables and pristine game seeds were unchanged. These automated loopback development checks do not replace a test through your actual caller program, owner acceptance, or checks of another game or Linux version. These focused installed-development results are retained as prior qualification for beta.11; this is not a new real-game test run. Test the delivered package through your actual caller program before opening a game to callers.

Start with a registered Door

On fresh beta.11 Linux, native Guess is installed at doors/sfxguess32/sfxguess32; NewsWire-X RSS uses doors/newswire-x-rss. Supplied Door guides are under docs/doors. Their original standalone qualification/source records keep their own scope; they are not new beta.11 game-test claims. Required game and DOS filenames remain as supplied.

Fresh installations include SFX Guess a Number, NewsWire-X RSS and X-Gate Game Server. The two local programs use the platform's native executable, Socket I/O and DOORDROP.INI in the node directory. Their initial access and execution minima are level 10. The X-Gate entry uses its saved RLogin settings. Updates preserve your existing definitions and menu choices.

Update NewsWire-X RSS trust data

Fresh installations supply the Mozilla CA bundle dated 2026-11-05 for NewsWire-X RSS. The Door reads its own config/cacert.pem file. Updating SFX preserves an existing Door's programs, feeds, configuration and trust file; it does not automatically refresh that existing CA file.

Both runtime ZIPs include a separate verified copy at Optional/NewsWire-X-RSS-CA-2026-11-05/cacert.pem, with provenance and instructions alongside it. To update an existing Door deliberately:

  1. Let current NewsWire sessions finish and keep the Door from launching while you work.
  2. Back up config/cacert.pem inside your actual NewsWire-X RSS folder. Check whether you added private or other custom trust certificates; preserve those requirements before choosing the stock replacement.
  3. Read the supplied copy's provenance and checksum instructions. If stock trust is appropriate for your Door, replace only its config/cacert.pem with that verified copy. Keep your feeds and other configuration.
  4. Run the Door and try one of your normal HTTPS feeds. Keep the backup and the actual error if a feed still cannot be read; a newer CA file does not fix every connection or feed error.

Open Doors in SFXConfig. On Windows, the Door editor separates Program, Access & Use, Automation and Menu Entry. On Linux, the browser form shows the fields appropriate to the command. Saving a definition does not install or run its program. Put the required program files on the BBS computer and follow the Door author's setup instructions.

Before allowing simultaneous Linux DOS callers

Use Allow multiple callers at once only when the game's own instructions support it, and configure the game itself. Each caller needs a different node and a private drop-file folder. For a single-name drop such as DOOR.SYS, choose Node Directory or Temporary Directory. Keep the game program and shared data in one game folder; two separate copies do not establish that callers can play together.

Test two different accounts at the same time, such as one SSH caller and one Telnet caller. Confirm that both are inside the same game and their names and node information are correct. If the game announces players entering and leaving, check that the first player sees the second player's name on both notices. Keep the first player in the game while the second returns to the BBS. Check saved progress and each caller's clean return to SFX. A one-caller pass does not establish simultaneous-caller support.

For the supplied Usurper 0.25 on Linux, the checked node setup uses FOSSIL Only, DOOR.SYS (52 lines) in Node Directory, one shared Start-up Directory, and USURPER.EXE /W /N%# /PF:\. SFX replaces %# with the caller's actual node; F:\ is that caller's DOS drop-file mapping. The explicit /N was needed for Usurper to show the correct separate game nodes. These flags belong to Usurper; check another game's instructions before using them.

Categories and menu entries

SFX supports up to 999 Door definitions, 999 additional categories and 99 numbered entries per menu. Door Menu is the root. Categories have a shared name (1–64 bytes) and separate Access and Execution requirements, each with minimum/maximum/exact mode, a level from 1–999 and Sysop Only. New categories start at minimum level 10 for both, with Sysop Only Off; the fresh root starts at minimum 1. Existing requirements stay intact.

Placement settingMeaning and initial value
Number on this menuAn unused number from 1–99. New placements suggest an available number.
Name on this menu1–64 bytes. Initially the selected Door or category name; edit it for this placement without renaming the shared definition.
DescriptionOptional text, up to 256 bytes; initially blank.
Destination categoryThe menu receiving this placement. Choose an existing category; initially the current menu.
Show a / Shared itemWhen adding an existing item, choose Door or Category, then the saved item. This creates a placement, not a new program definition.

Use Add Existing Door or Show on Another Menu to reuse a saved item. Use Edit Menu Entry / Move on Linux, or the entry/move controls on Windows, to change its placement. Up/Down changes its position. Category links cannot form a cycle or point back to the root as a child.

Duplicate Door makes a separate definition with copied settings and protected credentials. The copy starts disabled and unplaced; enter a copy name and review it before enabling it. Duplicate Category copies the category's entries, which still refer to the same shared Doors and nested categories. It is not an independent copy of every program.

Remove Menu Entry removes only that placement. Delete Door removes the shared definition and its placements. Deleting a category removes its subtree and the Door definitions it contains, including placements of those Doors elsewhere. Read the preview's Door, category and entry counts before the final confirmation. These actions do not delete program files. The root Door Menu cannot be deleted.

On Windows, adding a definition and its placement can involve separate saved steps. If the result reports that the definition was saved but placement did not finish, reload the catalog and place the existing definition; do not create another copy to compensate.

Door Bulletins

Use Door Bulletins for game scores, instructions, news or status. Each definition has a permanent number from 1 to 999. Callers select that number; gaps are allowed and removing a definition does not renumber the others.

Open Doors > Door Bulletins in Windows SFXConfig or the Linux browser controls. Choose Add New for an unused number, or select an existing definition to edit it. The list shows Number, Title, Source, Enabled and Last check. Last check is the last source result: Available, Unavailable or Not checked. Use Validate / Refresh to check the saved source again.

Choose Save Changes before Preview or Validate / Refresh. For a validation error that leaves the draft editable, correct the reported fields and choose Save Changes again. If the save outcome is uncertain or settings changed elsewhere, use Reload on Windows or Reload Saved Settings on Linux, then review the saved settings before trying another change. Remove Definition on Windows or Remove Definition... on Linux asks for confirmation and leaves the source files in place.

An enabled bulletin is public to authenticated callers who can reach the Door Menu, including callers who cannot launch its associated game. Use Enabled to control publication. If an associated Door is removed, its bulletin definition remains unavailable until you fix the source mapping.

On Linux, closing an edited bulletin offers Save, Discard or Stay; Close / Keep Draft keeps the allowed draft. Save closes only after the save and readback are confirmed. If the result needs checking, review the saved settings before another change. Discard removes unsaved text, not source files or an earlier confirmed save.

Use a static page

  1. Put the page in Display on Windows or display on Linux. Windows defaults use DB001.ANS/DB001.ASC through DB999.ANS/DB999.ASC. Fresh Linux defaults use db001.ans/db001.asc through db999.ans/db999.asc.
  2. Use CP437 with supported ANSI controls for ANS, or plain CP437 without ANSI controls for ASC. Supply a plain version for plain-text callers. Follow the Display file rules, including exact-security variants such as DB00110.ANS on Windows or db00110.ans on Linux for Bulletin 1 at level 10.
  3. Add the matching number and title, select Display file (DBnnn.ANS / .ASC), then Save Changes and Validate / Refresh. Preview the saved page.

Use a Door-generated page

  1. Configure the Door itself to write its score/status file in its working folder.
  2. Add a bulletin definition, choose Door-generated file, select the Door and enter a relative file such as SCORE.ANS. Use the actual filename and, on Linux, match its letter case. Choose ANSI or ASCII to match it.
  3. Save Changes, then Validate / Refresh and Preview the saved source.

The relative file starts inside that Door's Start-up Directory. SFX captures and validates the current file for callers. Generated macros and includes stay literal. When an ANSI-generated page is shown to a plain-text caller, an 80-column text projection preserves positioned score columns.

Sources are limited to 256 KiB each, with the existing 1 MiB aggregate source/rendered-output limits. If no valid current source is available, the enabled entry remains listed and shows This Door Bulletin is currently unavailable. Check its Sysop diagnostic and restore a valid source. SFX serves no stale copy; a later successful source read resumes viewing.

Preview, refresh and notices

Selection, Preview and Validate / Refresh recheck the current source. Preview uses an inert 80-column by 25-row viewport and does not launch the Door. It uses a sample caller at security level 999 for static exact-security selection. Use Plain-text preview to check the plain view.

Preview shows the last screen of long bulletins. Callers can read the whole bulletin.

A successful refresh of changed content can produce an ID/title notice for returning callers. Login reads successfully published revisions and does not open pages. Failed refreshes and identical rereads do not create new content notices. A successful source remap establishes a new publication; title/Enabled-only edits preserve the content identity. Switching graphics/security variants does not itself create an update; first capture of an additional static variant establishes its baseline.

What callers use

From any Door Menu or submenu, X opens the global index. Type the Bulletin ID and press Enter, or use a highlighted selection when light bars are available. N/P changes index pages. Follow the normal paging and Enter prompts while reading a bulletin; completion returns to the index. Q returns to the same Door Menu or submenu that opened it.

Optional DBUL.ANS/DBUL.ASC artwork appears first, followed directly by SFX's live number/title list and N/P/Q controls. A compact header leaves more room for that list. SFX supplies the entries and navigation from the saved definitions.

RLogin connection options

Enter rlogin host[:port] in Command Line. The default port is 513; allowed ports are 1–65535. The hostname or IP address is at most 253 ASCII bytes, without a URL, username or spaces. Use brackets for an IPv6 address with a port, for example rlogin [2001:db8::1]:513.

Command optionEffect when present
-qQuiet connection messages. Without it, quiet mode is Off.
-PDisable the return pause. Without it, pause is On.
-pUse the authenticated caller's login password and alias automatically, with traditional authentication.
-hUse the caller's password with Synchronet caller hashing and the caller alias.
-c nameExplicit client name, up to 127 bytes; otherwise blank.
-s nameExplicit remote server/account name, 1–127 bytes; otherwise the caller alias.
-t terminalTerminal string, 1–127 bytes; default ansi.
-T secondsConnection timeout, 1–120 seconds; default 10.

Use each option once and separate the flags. Do not combine -p or -h with each other or with -c/-s. Quote a name containing spaces. Passwords and pepper belong in masked fields, not Command Line; -H, -m, -v and -C are not supported.

Save Changes stores the reviewed settings without connecting to the remote BBS. Existing RLogin sessions use Ctrl-], then D, to disconnect from the remote board.

Resolve launch problems

Check the shared definition as well as its placement: Enabled, a nonblank command, category and Door requirements, and the caller's level. For a busy Door, check whether another caller or cleanup still owns it. For local programs, check the host-specific executable, existing start-up folder, I/O method, drop-file variant and permissions. A saved entry alone does not prove that its external program is installed or compatible.

Check Events and logs for the actual Door result. When asking for help, include the platform, Door name/code, program type, I/O and drop-file selections, plus the diagnostic text. Leave passwords and pepper out of the report.

If a DOS game reports a character already online after an interrupted session, check actual callers and game processes, then follow that game's recovery instructions. Usurper documents saved online state remaining after an abnormal shutdown; its ONLINERS.DAT can also exist normally when nobody is playing. Keep the game's data before changing it. SFX removes its own launch files and does not erase a game's saved online data.

BBS Transporter: Telnet gateway

BBS Transporter lets your callers visit a Telnet BBS you choose. In SFXConfig, open Doors > Door Menu > BBS Transporter, use Add/Edit, then open Program. Set Command Line to telnet host or telnet host:port. For example, telnet bbs.example.org:2323 uses port 2323; replace bbs.example.org with your destination. If you leave out the port, SFX uses 23. SFX handles the connection itself.

On Windows, choose “Telnet options...” to set “Telnet host”, “Port (default 23)”, “Terminal type” and “Connect timeout (seconds, 1-120; default 10)”. Choose “Use Telnet Options” to put the settings in Command Line, then choose “Save Changes”. The host allows up to 253 ASCII bytes, without a URL, username or spaces; the port is 1–65535. Terminal type is 1–127 bytes, default ansi. You can also use -t terminal and -T seconds in Command Line; on Linux, enter these directly. There are no command options for a login name or password.

While using the remote BBS in normal text mode, press Ctrl-X for the local Telnet Gate menu. D disconnects from that BBS and returns you to SFX. E turns local echo on or off. L lists callers on your SFX board. P sends private text to a local caller who can receive it. Q, Enter or Esc takes you back to the same remote connection. Outside BINARY mode, press Ctrl-X twice to send one Ctrl-X character to the remote BBS.

The gateway starts in normal text mode. If the remote board turns on Telnet BINARY mode, SFX passes Ctrl-X and the other data through unchanged. You cannot use the local menu in BINARY mode. This also applies if BINARY mode starts while the menu is open. Some boards turn it on at login, even when no file transfer is taking place.

The Telnet connection to the other BBS is not encrypted, even when your caller connects to SFX through SSH. Callers log into the other board themselves. Telgate does not look up or send their SFX password. Existing RLogin entries still use Ctrl-] followed by D to disconnect.
