Files > Groups & Areas

Linux SFXConfig: Choose the named group or area and use its actions below the list. Check the Editing name before Save Changes; browsing another row does not by itself replace an open editor. Storage paths are on the Linux BBS computer, and saving a folder choice does not move files. See editing and save results.

Groups organize the area list; an area owns its file listings and points to an existing storage folder. The caller must meet both the group's access minimum and the area's applicable access/download rules. Disabling a group or area keeps its settings and files while removing caller access.

Fresh board layout

A fresh board has an enabled Main group with access minimum 1 and these three areas. Updates keep your saved groups, areas and paths.

AreaFolder relative to SFXStarting behavior
General FilesWindows: Files/General; Linux: files/generalOrdinary area. Caller uploads off; downloads not restricted to Sysops.
UploadsWindows: Files/Uploads; Linux: files/uploadsReview area. Caller uploads on; downloads restricted to Sysops.
Upload to SysopWindows: Files/UploadToSysop; Linux: files/uploadtosysopPrivate submissions. Caller uploads on; browsing/downloads restricted to Sysops. Uploads and downloads do not participate in ratios.

All three start enabled, with access/upload/download minimum 1, inherited upload size, own-description editing off and content backup off. General Files and Uploads initially participate in ratios. The special review/private roles and permanent area numbers are not ordinary editable labels.

Folders, order and saving

Create the intended storage folder before selecting it. For example, Files/Utilities on Windows or files/utilities on fresh Linux refers to a folder inside that installation. Match the real spelling of an existing path you select; SFX does not rename arbitrary folders. Linux absolute paths start with /; Windows absolute paths use a drive and full path. Do not use a network-share path, ./.. components or a trailing separator. Save validates the folder and ownership/safety rules; it does not create the folder, move files into it or automatically adopt unknown files.

Changing an area's folder is refused while it has registered file records or pending intake/import/file/FTN work bound to the old path. Two areas cannot be configured to use the same folder. Use the file-management workflows for payload work instead of expecting a path edit to relocate content.

Use New Area inside the wanted group, or select an area and choose Insert Before/After. Move Up/Down changes caller display order. Area numbers are permanent and assigned when a new area is saved; reordering does not renumber them. At most 999 permanent area numbers can be allocated. The Linux catalog browser lists by permanent ID and shows display order separately, so its editing list is not a preview of caller menu order.

Save Changes writes the reviewed settings without a BBS restart. Read the result before another edit. Reload fetches current saved values; Reconcile checks an unresolved operation. A refused save keeps the previous configuration authoritative. Check the text/level ranges, existing folder, duplicate path, permanent identity and whether another session changed the catalog.

Delete a group

Stop the BBS and close File Manager/file work before Delete Group. Review its areas, file listings and inspected disk contents. Choose explicitly between Remove from SFX only - keep files on disk and Delete from SFX and delete files on disk. The latter permanently deletes the reviewed files. Empty folders, internal history and permanent numbers remain.

Confirm only after checking the exact group and choice. Cancel before starting keeps the group, areas and files. If deletion was interrupted, use the saved Continue Deletion or review/reconcile flow; completed disk deletions cannot be undone. An unresolved result is not proof that nothing happened. Follow the specific refusal if pending work or a protected area prevents the operation.

Caller scan preferences

From Your Settings > Scan Preferences, choose D, New File Scan Date to change the saved scan date. The date prompt starts on a new line. Enter a real date in YYYY-MM-DD form, no later than the saved scan date. An empty Enter keeps the date unchanged and returns to the preferences. An invalid date is refused.

N toggles New File Scan at Logon. L toggles File Light Bars when the Sysop allows them. These remain separate choices; changing the scan-date label does not reset either preference.

Caller file list markers

A * in the column immediately before a filename means the file is queued. A blank in that column means it is not queued. Read the marker alongside the filename when reviewing the list.

Files > Transfer Policy

Linux SFXConfig: Save Changes keeps this editor’s board-wide limits. The upload-scan choice is saved separately under ClamAV; a transfer-policy save does not start a transfer or update definitions. See editing and save results.

These are the board-wide caller file-transfer defaults. Updates preserve saved values. An area's upload cap, an explicit security-level count rule, and caller exemptions can change which limits apply to a particular transfer.

SettingFresh valueRules
Maximum caller upload bytes104,857,600 bytes (100 MiB)Whole bytes from 1 to 1,073,741,824 (1 GiB). Applies to caller uploads; an area may override it. It is not a Sysop-import size setting.
Light-bar selection default for new callersOnOn/off. Seeds a caller's file-list choice when no saved choice exists; existing saved caller preferences are kept.
Limit successful downloads per BBS-local dayOffOn enables the Daily files value below.
Daily filesNo enabled limit1-1,000,000 whole files when enabled. The day follows the BBS time zone.
Enable file-count ratioOffOn requires explicit Downloads and Per uploads values.
DownloadsNo prefilled ratio1-1,000,000 whole files when the ratio is enabled.
Per uploadsNo prefilled ratio1-1,000,000 whole files when the ratio is enabled.

For example, set Daily files to 20 and turn its limit on to allow twenty successful downloads per BBS-local day. Counts are files, not bytes. A transfer in progress reserves allowance so simultaneous transfers cannot each spend the same remaining slot. Failed transfers do not become successful-download counts.

A ratio of 3 downloads per 1 upload gives three initial participating downloads, then three more for each eligible upload. More generally, total entitlement is the Downloads value plus the whole-number part of eligible uploads × Downloads / Per uploads. Already used participating downloads count against that entitlement. Area participation flags and level/caller exemptions affect eligibility; turning a ratio on does not grant access to a hidden or private file.

Choose Save Changes and read the result. These settings save without a BBS restart and are checked for later transfer admission; saving does not start a transfer. If a save result is uncertain, use the offered Reconcile action or reload the saved settings before another change. For an invalid value, check bytes versus files, the numeric ranges, and that each enabled count has an explicit value. Use the enable checkbox to turn a count off; zero is not a valid enabled count.

Log off after transfer

Before a File-menu upload or download, the caller sees Log off after transfer? [Y/n]. Enter keeps the starting Y choice. Choose N to stay online and use the ordinary transfer report and return.

With Y, SFX shows the transfer report and starts a visible 10-second logoff countdown automatically. There is no final Enter prompt before the countdown. Press A to abort logoff and return to the File menu, or D to disconnect now. If the caller does nothing, SFX logs off when the countdown expires.

Read the transfer report for completed, failed or held files. The logoff choice does not turn an unsuccessful transfer into a successful one. This choice belongs to File-menu transfers; the QWK menu has no added logoff choice.

Files > Security-level Count Rules

Linux SFXConfig: Select the intended security level from the named list, review its inheritance and count fields, then Save Changes. This edits the level’s file-count rule, not one caller’s account or area permissions. See editing and save results.

Select an existing active security level. This page changes file-count rules for that level; the level's name, calling-time allowances and Sysop threshold remain under Users & Access > Security Levels. A level starts by inheriting the global file-count policy, and updates preserve its saved choice.

SettingMeaning
Inherit global file-count policyOn uses Files > Transfer Policy. This is the starting choice. Off enables the level's explicit choices below.
Limit successful daily downloadsOn applies this level's Daily files value. Explicit Off removes the daily limit for this level instead of falling back to the global limit.
Daily files1-1,000,000 whole files when enabled.
Enable file-count ratioOn applies this level's explicit ratio; Off removes that ratio requirement for this level.
Downloads1-1,000,000 whole files when ratio is on.
Per uploads1-1,000,000 whole files when ratio is on.
Exempt this level from daily download countsWaives the daily-count restriction. Starts off.
Exempt this level from file-count ratiosWaives the ratio restriction. Starts off.

For example, to give level 20 a daily allowance of 50 files, turn inheritance off, enable its daily limit and enter 50. Choose the ratio policy you want for that level too: an explicit level record replaces the global count rule rather than overriding just one number. Enabling inheritance again uses the global rule and clears the level's separate count/exemption choices.

Save Changes applies the rule to later download checks without restarting the BBS. Area access, download permissions and private-file protection still apply. If the selected level was removed elsewhere, discard the stale draft and select an active level. Reload or reconcile an uncertain result before resubmitting.

Files > Caller Exemptions

Linux SFXConfig: Find and explicitly select the caller before editing the exemption fields. Save Changes affects that caller’s file-count exemptions; check the name and result before choosing another caller. See editing and save results.

Find and select the caller before changing either checkbox. Exempt caller from daily download file counts and Exempt caller from file-count ratios both start off when no exemption has been saved. They are independent on/off choices, and updates keep existing choices.

For example, turn on only the daily exemption to waive that caller's daily file count while retaining any applicable ratio. An enabled caller exemption adds to any level exemption. Turning a caller checkbox off does not cancel an exemption granted by the caller's security level.

Choose Save Changes and read the result. It applies to later admission checks without a BBS restart. These checkboxes do not grant access to private areas, change an area's upload cap or waive file permissions. If the caller is missing or the result is uncertain, reload the exact caller and review before retrying.

Security > ClamAV

Linux SFXConfig: Save Changes keeps only the caller-upload scan choice. Status refresh, definition updates, log viewing and cancellation remain separate actions. Check engine and definition readiness as well as the saved checkbox. See editing and save results.

On supported Windows 10/11 hosts, Setup's Install Portable ClamAV now? choice is optional. Yes downloads/verifies the engine and attempts the initial definitions; No skips for now, and Cancel returns to Setup. Later, use SFXConfig > Security > ClamAV. Read the engine and definition result rather than treating an accepted install request as ready scanning.

Installing or skipping the component is separate from reviewing Scan Uploads. Explicitly saved choices remain saved; the untouched starting-policy cases below still apply. When a required scan cannot complete, the new upload is held privately for review rather than reported clean. Completing the BBS first-run wizard does not establish AV readiness.

Scan caller uploads is a saved board choice. On supported scanning hosts, saving it on enables scanning of new caller uploads; saving it off disables that scan requirement. This choice saves separately from Transfer Policy. Sysop imports are not automatically scanned by this setting.

Installation or saved stateStarting scan choice
Linux, or supported Windows 10/11, with the ClamAV component present and the initial scan policy still untouchedOn when SFX initializes that component. This does not mean the engine or definitions are ready.
Fresh policy without the optional componentOff. Adding the component later can enable an untouched initial policy; it does not replace an explicitly saved choice.
An explicitly saved On or Off choice on a supported scanning hostKept on normal updates and later initialization. Check the saved checkbox rather than assuming every installation starts alike.
Windows 7 SP1Off. SFX does not support ClamAV scanning on this platform.

When scanning is on, an unavailable or incomplete scan holds a new caller upload privately rather than releasing it as clean. Check the installed engine, definition readiness and the scan result before deciding what to do with a held upload. Having definition files present is not the same as a verified ready scanner.

Windows 7 SP1 has no ClamAV scanning support in SFX. Its upload-scanning choice is kept off. On Windows 10 and 11, the Portable ClamAV page can install the optional component later. Stop the BBS and Control Panel before Install Portable ClamAV...; SFXConfig may stay open. The Linux page reports its installed engine and definition status and provides definition-update controls.

Optional ClamAV work can continue after the Windows Control Panel opens. This does not make an unverified engine or incomplete definitions ready to scan. SFX still verifies the engine before scan or definition-update use and holds uploads whose required scan cannot complete.

Verify ClamAV after Prepare SFX on Windows

On Windows 10 and 11, Prepare SFX gives a prepared copy its own installation identity and reports if Portable ClamAV needs attention. If an earlier Prepare left the ClamAV receipt tied to the previous identity, stop the BBS and close its controls. Run matching Setup, select that exact existing folder and follow the normal update or repair review and backup steps.

Setup can issue a receipt for the current board when it verifies the installed engine and matches the previous identity to that board's protected Prepare history. It reuses the verified engine and can update an untouched, generated FreshClam configuration to use the selected board's folder.

  • Repaired for this installation means Setup corrected the receipt or generated FreshClam configuration for the selected board.
  • Existing Portable ClamAV verified means the installed engine and its receipt passed verification.
  • If Setup preserved the existing FreshClam configuration, the engine passed verification and the configuration needs attention. Keep the existing file and review the ClamAV diagnostic.
  • If Setup could not verify the existing Portable ClamAV receipt or engine, it preserved the component files. Keep the reported diagnostic and follow the guidance for that installation.

Open SFXConfig > Security > ClamAV and check engine and definition status separately. Review your saved upload-scan choice there as well. An upload stays held privately when its required scan cannot finish.

Definitions and update controls

Turning upload scanning off does not turn definition updates off. Runtime owns the automatic daily UTC update attempt. Update Definitions Now requests a manual update; it does not turn scanning on or override a vendor cooldown. Check the last attempt, last successful check, last definition change and reported result separately. An unchanged successful definition check is different from a failed check.

Use Refresh Status to read current state and View Update Log for the latest update output. On Linux, that view contains at most 64 KiB of the latest output, not a permanent history of every update. Cancel requests cancellation of the active operation; wait for the reported result and cleanup before starting another. Save Changes writes the scan choice without a BBS restart, and does not itself install the engine, update definitions or rescan existing files.

If scanning is unavailable, check engine verification, definition readiness and the diagnostic. Use matching Setup repair when the Windows page reports an unverified installation. If a settings save is uncertain, reconcile or reload it before retrying; do not infer a successful save from a checked box alone.
