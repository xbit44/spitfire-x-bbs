Get your BBS ready

Windows installation and first run

Run the matching SFX-BBS-Setup.exe and choose your installation folder. A fresh install opens that board's First-Run Setup in Control Panel automatically after installation finishes. Choose Finish Later in the wizard if you want to configure the board later.

Use the Spitfire-X BBS shortcut for this board if you selected it. If that name is already in use, Setup keeps the existing shortcut and creates a separate numbered name. Without shortcuts, open Bin\SFXControlPanel.exe under your selected SFX folder directly. Opening SFXConfig first is not a replacement for initial board setup.

Complete the board identity and initial Sysop choices in First-Run Setup. Save Setup and Start BBS deliberately commits the settings and configured System Sysop, reads saved settings back from Runtime and confirms configured caller listeners. Review that action before accepting it. Finish Later leaves initial setup pending.

Check saved/readable configuration separately from actual listener status. A bind/start failure can follow a successful save; the result retains that listener diagnostic. Review the configured address/port and saved values rather than treating it as an empty board or recreating the initial account. See Windows startup and readiness.

If SFXConfig says the board needs initial setup, open this same installation's Control Panel, complete First-Run Setup and reopen SFXConfig. Other verification, IPC or saved-configuration read failures retain their own diagnostics; do not treat them all as an empty board or delete data to retry setup.

Setup separately offers Install Portable ClamAV now? on supported hosts. Yes verifies/installs the engine and attempts initial definitions; No skips it for now, with later installation in SFXConfig > Security > ClamAV. Engine/definition readiness and the saved upload-scan choice are separate. Read ClamAV policy and held uploads.

For maintenance or removal, use the Windows update/repair or uninstall instructions. Keep each board's installation folder and shortcuts distinct.

Set your board name and node count

These settings are in SFXConfig on Windows and Linux. The starting values below are for a new board; an update keeps your saved board settings. Setup may already have changed the name and node count to the choices you entered.

General > Board Identity: BBS name

Linux SFXConfig: Change the BBS name in its grouped editor. QWK, System Sysop and private-message colors use their own controls; Save Changes for the name does not save those choices. See editing and save results.

This is the public name used to identify your BBS to callers. Enter 1-64 printable ASCII characters. Spaces are allowed inside the name, but not at either end. Do not use an equals sign, tabs or line breaks. The starting name is Spitfire-X BBS; for example, you could use North Valley BBS.

On Windows, choose Save Changes. On Linux, save the page and read its result. A name-only change does not require a BBS restart; if the BBS is stopped, the saved name is used when it starts. Existing screens already shown to a caller are not rewritten. If Save refuses the name, check its length, leading/trailing spaces and unsupported characters. If another session changed the settings, reload the current values before editing again.

Board Identity also has separate System Sysop and private pipe-color controls and QWK settings. Their own Save actions are separate from the BBS name.

System > Nodes: Number of nodes

Linux SFXConfig: Change Number of nodes and use Save Changes. Follow the saved result’s restart requirement; editing this count does not silently disconnect callers or replace the Control Panel’s live node controls. See editing and save results.

This sets the size of the BBS caller-node pool. Use a whole number from 1 to 128; the starting value is 4. For example, enter 8 to configure eight logical nodes. It is a node count, not a time limit or a port number. Listener and connection limits still apply.

Windows labels the field Configured logical nodes (1-128) and its button Save Node Definition. Linux labels it Number of nodes. Saving a changed count requires an orderly BBS restart. Save does not automatically disconnect current callers. Plan the stop, then restart and check the active count. Enabling or disabling an individual node in the Control Panel is a separate live action.

If the count is rejected, use digits only and stay within 1-128. If the saved value differs from the active value, check whether the restart is still pending; saving repeatedly will not perform that restart.

Read the Save result

Saved settings and currently active settings can differ. Read whether the change was applied, is waiting for a safe point, or needs a restart. A stale settings revision means another change was saved first: reload and review before trying again. A refused save is not confirmation that the new value took effect.

General > Regional & Time

Linux SFXConfig: Choose the packaged BBS time zone and use Save Changes. Read the saved and active result; the browser computer’s time zone does not choose the BBS zone. See editing and save results.

BBS time zone chooses the zone used for BBS timestamps and scheduled jobs. Windows presents the installed Windows time-zone keys in a list; first-run setup initially selects the computer's current zone. Linux accepts a named time zone such as America/Los_Angeles or Etc/UTC, with a maximum of 128 characters. Linux first-run setup starts with Etc/UTC. Check the choice during setup rather than assuming both platforms start in the same zone.

On Linux, use a zone supported by SFX's packaged time-zone data. A name such as America/Los_Angeles includes its seasonal clock rules; do not enter a display abbreviation or a bare hour offset. On Windows, choose the appropriate installed key, such as Pacific Standard Time, from the list.

Choose Save Changes on Windows, or save the Linux page. A time-zone-only change can apply without a BBS restart; future scheduled eligibility is recalculated. Historical UTC values and recorded offsets are not rewritten. Existing calls can retain their captured time context. Updates preserve the saved zone.

If Save refuses a zone or reports that future job times cannot be calculated, check the name and the available time-zone data. Read the result and verify the next scheduled time before relying on a changed schedule. This is the BBS time zone; changing it does not change the computer's operating-system clock.

General > System Information

Linux SFXConfig: Save Changes keeps the opening date in this editor. Save the statistics choice with its separate button; neither action resets past totals. See editing and save results.

This BBS began on (YYYY-MM-DD) sets the opening date shown in public System Information. Enter a real calendar date, for example 1994-06-18. Use four year digits, two month digits and two day digits separated by hyphens; do not enter a time or a locale-specific date such as 06/18/94.

Until you set a historical date, the displayed default comes from the board's retained installation/database initialization date in the BBS time zone. It is not the current Runtime start date. A saved date survives updates and repairs.

Choose Save after entering the date. It saves independently from statistics and does not require a BBS restart. Windows also provides Reload to fetch the current date. If the date is invalid or another session changed it first, review the message, reload as needed and retry your intended date. No statistics or caller records are reset by this field.

System Information: Exclude Sysop from Statistics

This on/off choice starts on. It excludes future Sysop logons, their system time online and their recent-caller summaries from the public statistics. Personal account history and existing totals remain. Turn it off if you want future Sysop logons included; an update preserves your saved choice.

On Windows, choose Save Statistics Setting; on Linux, save the statistics choice separately from the opening date. It applies to future logons without a BBS restart, so it is not a way to recalculate earlier totals. Save or discard an unsaved opening-date edit before submitting the statistics change.

Connections > Telnet & SSH

Linux SFXConfig: Edit the grouped Telnet, SSH and hostname-display choices, then Save Changes. Follow the actual applied, waiting or refused result; a saved port does not prove the listener opened. See editing and save results.

These settings choose where callers connect to SFX. Each connection type has its own enable switch, IPv4 listen address and port. A fresh board starts with the values below; an update keeps your saved choices.

SettingStarting valueWhat to enter
Enable TelnetOnOn accepts new Telnet connections; off closes the Telnet listener.
Telnet listen address / IPv4 bind0.0.0.0An IPv4 address on this computer, or 0.0.0.0 for all its IPv4 addresses.
Telnet port2323A whole number from 1 to 65535.
Enable SSHOnOn accepts new SFX SSH connections; off closes that listener.
SSH listen address / IPv4 bind0.0.0.0The same address rules as Telnet.
SSH port2222A whole number from 1 to 65535.
Hostname Lookup for Telnet and SSH / Look up caller hostnamesOnShows available caller hostnames as display hints. Numeric source addresses remain authoritative for access rules.

Use four decimal address parts, each 0-255, separated by dots. For example, 127.0.0.1 restricts a listener to this computer. Do not enter a hostname, an IPv6 address, a subnet suffix or leading zeros such as 192.168.001.12. The address is this BBS computer's address, not a caller's address. An address and port must remain valid even when its listener is disabled.

Enabled Telnet and SSH listeners cannot share a port when their addresses are identical or either address is 0.0.0.0. Keeping ports 2323 and 2222 avoids that conflict. Another program may already own a selected endpoint; SFX refuses a listener change it cannot bind. Its SSH listener is separate from an operating-system SSH service. On Linux, ports below 1024 need the permission described under the Linux service plan.

Test a caller connection with IPv4

For a terminal on the same computer as the BBS, use the literal address 127.0.0.1. Match the connection type and the actual saved listener port: for the fresh defaults, a SyncTERM Telnet entry uses 127.0.0.1 and port 2323; an SFX SSH entry uses 127.0.0.1 and port 2222. Updates keep existing ports, so check your board's settings before copying these examples.

A terminal's Telnet/SSH entry takes a host address and port, not a browser URL. Do not put http:// or https:// in its host field. The Linux browser-management URL, an operating-system SSH connection and an SFX caller connection are separate endpoints.

If localhost fails, try 127.0.0.1 explicitly: localhost can resolve to IPv6 while the configured SFX listener uses IPv4. This does not require changing the computer's IPv6 settings. From another computer, use the BBS computer's reachable IPv4 address, for example 192.168.1.50, and its configured caller port. There, 127.0.0.1 would point back to that other computer. 0.0.0.0 is a listen-on-all-IPv4 setting, not a destination to enter in SyncTERM.

Start BBS, confirm that the selected listener actually reports running, then check the terminal's protocol/address/port. SSH must use the SFX SSH port; Telnet must use the Telnet port. A stopped BBS, disabled listener, conflicting port or loopback-only bind can explain a refused connection. Read the displayed listener failure; a saved setting or visible Control Panel alone is not proof of readiness.

Save and connection timing

On Windows, choose Save Server Settings. On Linux, save the page and read its result. A single-listener change can apply while callers are connected; established calls are kept. Turning a listener off stops new connections through it. Both listeners may be disabled.

Changing both listener endpoints together, or changing hostname lookup together with an endpoint, requires zero active callers. With callers present, that combined save is refused. Changing hostname lookup by itself is saved but waits for active callers to finish. If you also have a pending change that requires a restart, follow the displayed restart result. When the BBS is stopped, the saved endpoints are used at its next start.

If Save refuses an endpoint, check the address, port range, overlap with the other listener and whether another program is using it. Read the reported failure before trying again; a refused change is not a new listening endpoint. After a successful change, use the new address and port in the caller's client.

Check a caller login

After a successful login, Windows and Linux show Your IP address is: in the information directly below the greeting. This is the numeric address for the current caller connection. A local connection may show its loopback address.

Connections > External Client

This optional profile launches a local Telnet client for a selected BBS node. It does not configure a public Telnet listener. A fresh profile has no configured executable; an update keeps an existing saved profile. On Windows it belongs to the current operator for this installation. On Linux it belongs to the account that owns the SFX folder.

FieldWindowsLinux
Client type / Desktop clientSyncTERM 1.10 series, or Custom command-line client.None, SyncTERM, or Custom.
ExecutableFull path to an existing .exe; Browse can select it. SyncTERM must be named syncterm.exe.Full, normalized path to an executable program, up to 3072 bytes. SyncTERM must be named syncterm.
Custom arguments1-8 separate arguments, one per line, up to 512 characters each.1-8 separate arguments, one per line, up to 512 bytes each.

Leave Custom arguments empty for the SyncTERM type; SFX supplies its local Telnet address and port. For Custom, include {HOST} exactly once and {PORT} exactly once across the arguments. SFX replaces them with the loopback address and the selected node's connection port. Other brace placeholders are invalid.

If your client's documented syntax is client host port, use these two argument lines:

{HOST}
{PORT}

Use the actual syntax your client expects. One line is one argument, so spaces within a line belong to that argument. Do not add shell quoting around the entire argument or expect shell commands and expansion. The complete launch is bounded to 4096 characters on Windows and 4096 bytes on Linux, including its required formatting; a long path can leave less room for arguments.

Choose Save Client on Windows, or save the Linux profile. Saving checks the profile and applies it to the next local launch; it does not start a program or restart the BBS. Clear / Reset removes the configured profile without removing the client program. Review a failed save before trying a launch; check the absolute path, client type, argument count and the two required placeholders.

Windows uses the profile for the next exact-node local launch. On Linux, management and the BBS must already be running; use the local desktop launcher command shown by SFX for the wanted node. Browser Control Panel Logon always uses the built-in browser terminal. Saving a Linux profile through a LAN browser does not launch a program on that browser's workstation. See Linux browser controls for the local launch flow.

Security > Connections

Linux SFXConfig: Edit the per-source limit and exact address exceptions, then Save Changes. Follow the required BBS restart; hostnames are not access authority. See editing and save results.

These limits control simultaneous connections from the same numeric source address. They do not add nodes to the board, bypass caller access rules or replace the separate failed-login controls.

SettingStarting valueRules and example
Connections per source address2A whole number from 1 to 128. For example, 8 permits up to eight connections from an address, subject to available nodes and the other admission checks.
Source address exceptionsEmptyUp to 32 individual canonical IP addresses, each with a limit from 1 to 128. Use one IP|limit entry per line, such as 192.0.2.1|8. No hostnames, subnets or duplicate addresses. Clear the list for no exceptions.

An exception replaces the usual source limit for that address; it does not exempt it from all security checks. Callers sharing one outward-facing address share its connection allowance. The board's node count still caps overall capacity. Windows also displays a disabled Legacy per-account limit (retained, not used) field. It is not an effective concurrency setting. Ordinary callers have one session; only security level 999 may have multiple sessions, up to the configured node count. Raising or lowering the Sysop threshold does not change that special level-999 rule.

On Windows, choose Save Connection Security. SFXConfig reviews changes that allow more connections from an address. On Linux, save the page. Changes to the source limit or exception list require a BBS restart. Existing saved choices survive updates. If a list is refused, check the | separator, canonical address spelling, duplicate entries, limit range and 32-entry maximum.

Linux known issue Some otherwise valid multi-address lists can be refused, including a list containing both 192.0.2.1|4 and 192.0.2.10|4. Manually rearranging these lines does not fix the problem. If this affects your list, keep the working saved policy; this issue is awaiting a fix.

System > System Password

Linux SFXConfig: Use the separate permanent System Password replacement form and its review. It is not an ordinary caller-password reset. Replacement values are cleared from the form, and an uncertain result needs its specific password-status review. See editing and save results.

The permanent System Password protects Sysop authentication and management. It is separate from each caller's account password. Setup requires you to choose it; there is no password value to copy from this guide. An update preserves the existing credential.

Enter the replacement in New permanent System Password and enter the identical value in the confirmation field. You do not need to type the old value into this replacement form. The new value must meet the active password policy: Standard permits 4-128 printable ASCII characters, while Strong requires 15-128 and the local blocklist/context checks. Do not leave either entry blank.

On Windows, choose Replace Permanent SY:... and review the replacement. On Linux, submit the System Password form and its in-page review. A successful replacement applies without a BBS restart and disconnects active Sysop sessions; ordinary callers remain. Sysops must use the new password when they authenticate again. The form does not display or recover the old password.

If the password policy or saved revision changed, refresh and enter the replacement and confirmation again. If the response says the password was replaced but session cleanup was not confirmed, check Runtime status; do not blindly repeat the replacement.

Security > Failed Login Attempts

Linux SFXConfig: Select the exact delay scope and subject, then use the reviewed Clear Login Delay action. This is an action on a temporary delay, not an ordinary saved policy or a global password reset. See editing and save results.

Repeated wrong passwords cause temporary login delays, even when BotGate is off. They expire automatically. This page clears one selected delay so a caller can try again sooner; it does not change the password policy or configure a permanent exemption.

Clear login delay forIP address or user number
One IP addressOne canonical numeric address, without a hostname, subnet suffix or port.
One userThe positive user number shown in Accounts, written without leading zeros; not the caller's name.
Shared System PasswordLeave the subject blank.
Shared BBS login delayLeave the subject blank.

The form starts with One IP address selected and an empty subject; it has no saved default to apply on upgrade. For example, choose One user and enter that caller's displayed user number to clear only the account delay. Choose Clear Login Delay... on Windows, or the Linux clear action, review the exact target and confirm. The action is logged and does not need a BBS restart.

Password checks, the three-failed-attempt disconnect and other login delays still apply. A short wait already in progress may finish normally; new failed logins can create another delay. This action does not clear a BotGate IP ban. If completion is not confirmed, check the result before retrying. If a subject is rejected, use the required numeric address or user number, or clear it for a shared delay.

Security > BBS Security

Linux SFXConfig: Review BBS Security and the two login-challenge choices in their named groups, then Save Changes. These choices are separate from enabling the SSH listener or granting network access. See editing and save results.

BotGate checks incoming sources and can ask callers to complete a short human challenge. These four choices start as shown below on a fresh board. An update keeps existing choices.

SettingStarting valueEffect
BotGate enabled / Enable BBS SecurityOnThe main switch for BotGate filtering and challenges.
Telnet / Challenge Telnet callersOnIncludes Telnet callers in BotGate source filtering and the human challenge. Despite the shorter Linux label, this choice affects Telnet filtering too.
Challenge new SSH registrationsOffAdds the human challenge for new SSH registrations. Existing SSH account logins do not receive this registration challenge. SSH source filtering still applies when BBS Security is enabled, whether this choice is on or off.
Challenge timeout / Challenge time20 secondsA whole number from 5 to 120 seconds. For example, 30 gives the caller thirty seconds to complete the challenge.

On Windows, choose Save BotGate Settings; on Linux, save the page. An applied change does not require a BBS restart and is used for new calls. A challenge already in progress keeps the settings captured for that call. If the BBS is stopped, the saved choices apply when it starts. Read the actual result if other settings are pending.

The SSH checkbox is not a general SSH-filter switch. For example, leaving it off still allows the configured source rules to refuse a blocked SSH source. If legitimate callers cannot connect, inspect the recorded refusal and the matching rule rather than changing the challenge timer to address a source block. A missing or invalid rules snapshot can prevent activation; check the rule status. A failed feed update is reported separately from local rules and challenge settings.

Windows and Linux BBS Security have a rule-file selector, editor, Save Rule File, Reload Rules and Update Threat Feed Now. Saving the protection settings is separate from saving a rule file. Selecting a different file is not a save; read and resolve the unsaved-change review. Temporary bans remain read-only.

BotGate rule files, Geo lists and feed updates

Local lists live under BotGate/can on Windows and botgate/can on Linux. Fresh lists are empty; existing rules are preserved, and older saved rules are migrated when the file layout is initialized. On Security > BBS Security, choose the Rule file, edit Rule-file contents and choose Save Rule File. That action writes only the selected file; the page's protection-setting Save is separate. Preserve the files' private ownership and permissions.

Reload Rules rereads the selected saved file from disk. It is not a command to force immediate filter activation. Resolve the offered Save, Discard or Stay choice before leaving unsaved edits. A save refuses an externally changed baseline; reload and review it. A successful save is read back before its draft clears. If the reply is lost, retain the draft and use Check Save Result instead of sending another save. A differing readback requires explicit review, discard or reload.

FilePurpose
ipfilter_exempt.cfgExempt matching sources from BotGate filtering, Geo, downloaded-feed blocks and BotGate per-IP arrival throttling. Human challenge and login still apply.
ip.canBlock matching source addresses or ranges.
ip-silent.canBlock matching sources without a log line for each attempt. Dashboard refusal totals still count them.
host.canBlock forward-verified hostnames. A DNS failure skips this check, not the other protection checks.
temp_ip.canBBS-managed temporary bans with expiry. Read-only in the editor; expired bans stop blocking. Do not use it as your permanent manual block list.
feed-exempt.canIgnore downloaded-feed matches only. Local address, Geo and hostname blocks still apply, as do challenge and login.

Use one rule per line. Address rules accept IPv4 addresses, canonical IPv4 CIDR networks, and */? wildcard patterns. CIDR host bits must be zero: use 192.0.2.0/24, not 192.0.2.7/24. Hostname rules also accept letters and hyphens and match without case sensitivity. Prefix a rule with ! for an exception within that same file. It does not override a block in a different list.

# Example ip.can: block a range except one address
192.0.2.0/24
!192.0.2.10

Blank lines and lines starting with # or ; are ignored. A space, tab, semicolon or hash ends the rule token, allowing a comment. A file can contain up to 10,000 rules and 1 MiB; each line is at most 1,024 bytes and each rule token at most 253 bytes. The Windows and Linux editors load files up to 65,535 bytes; use an owner-authorized text editor for larger valid files.

While the BBS is running, valid saved rules activate through its normal reload cycle, usually within about two seconds. With the BBS stopped, they are used at its next start. An invalid candidate does not partially activate; the last good rules remain active. Check the rule status after editing. If a file changed externally while an editor was open, Save refuses the stale edit; reload and review before trying again.

Geo block files

Add or remove country/range .txt files under BotGate/geo on Windows or botgate/geo on Linux. Their active ranges are blocks, not an allowlist. Use lines such as deny from 192.0.2.0/24; these accept IPv4 addresses or canonical CIDR, not wildcard patterns. Comments and common order allow,deny/allow from all wrapper lines are ignored.

Each Geo file must contain at least one valid range. Limits are 64 files, 16 MiB per file, 32 MiB total and 500,000 ranges per file. Filenames are at most 64 characters using letters, digits, dots, hyphens or underscores. Geo files use the same reload cycle and last-good-rule protection. Check the Geo summary after a change.

Downloaded threat feed

Update Threat Feed Now queues the existing feed worker while the BBS is running and the updater is available. A duplicate request during an active update or an unavailable worker is refused. Under Downloaded threat feed, read the running/available/updating state, progress, feed entry/byte counts, last attempt, last success, result and rule readiness. Timestamps are UTC. Refresh Feed Status reads the current state without requesting another update. Queued or downloading is not proof of successful activation.

A failed update preserves a valid earlier feed. Automatic refresh remains due 24 hours after success; a failed attempt schedules another attempt after an hour. Feed-only exceptions do not change local rules, challenges or login.
