Users & Access > Accounts

Linux SFXConfig: Use Find, explicitly select the named caller or choose New User, then edit the grouped fields. Save Changes saves the account editor; password reset and account-state actions keep their separate reviews and session effects. See editing and save results.

Use Find with a name prefix or the user number shown in Accounts, then select the record. Previous and Next move through the results. Check the selected name and number before saving or using a password or account-state action. On Windows, the fields are divided into Personal and Security tabs.

FieldWhat to enter
Name1-30 printable ASCII characters. Use single spaces between words and none at either end. Account-name comparisons ignore letter case, so changing capitalization does not create a distinct name.
Real nameOptional, up to 64 printable ASCII characters. Use single spaces between words and none at either end.
LocationOptional, up to 64 printable ASCII characters, without leading/trailing spaces.
PhoneOptional, up to 32 printable ASCII characters, without leading/trailing spaces.
EmailOptional, up to 254 printable ASCII characters, without leading/trailing spaces.
Birth dateBlank or a real date in YYYY-MM-DD form, such as 1980-05-21.
SexM, F, X, or blank.
Assigned levelAn active configured security level from 1 to 999. This changes the selected caller's assignment; edit shared level definitions separately in Security Levels.
Allow automatic purgeOn allows the account to be considered by automatic purge policy; off protects it from that eligibility. This checkbox does not itself run a purge.

There are no replacement defaults for an existing caller: the form loads that record, and an update preserves it. Optional profile fields may be left empty. To rename River Runner, edit Name and save; do not create another account merely to change the display name.

Create or save a caller

Choose New User, enter a name and an initial password twice, then Save. New profile fields start empty. The account receives the configured New User level when saved and starts with automatic-purge permission off. Its user number is assigned on Save. After creating it, find and select the saved record before changing its assigned level or purge choice.

Passwords must meet the active caller password policy. For an existing caller, ordinary Save writes the name, profile, assigned level and purge choice; password reset is a separate action. Saved profile changes do not require a BBS restart. Renaming disconnects that caller's sessions. Reduced access applies to online callers; newly granted Sysop access requires the caller to log in again and complete System Password authentication.

Reset a password

Select the existing caller, save or discard ordinary record edits, enter the temporary password in Password and Confirm, then choose Reset Password... and review the action. The reset disconnects that caller's sessions. The temporary password expires after 72 hours or first use, and the caller must replace it at login. Entering a password and choosing ordinary Save does not perform this reset. Passwords are never shown as recovered existing values; enter them again when a retry requires it.

Deactivate, reactivate or delete

Deactivate User disconnects the caller and blocks login until the account is reactivated. Reactivate User returns it to active status; the usual password, access and network checks still apply. Delete User blocks login and disconnects sessions, while retaining the deleted-account record and retained session/audit history. It does not purge that history or provide an undo that recreates the deleted account.

The last usable Sysop is protected. The designated System Sysop also needs an eligible replacement before deactivation, deletion or demotion. If an action is refused because the record or policy changed, reload and review. If a result says a change committed but cleanup did not finish, inspect the saved account and Runtime status before doing anything again; do not treat it as an untouched record.

Users & Access > Security Levels

Linux SFXConfig: Choose a named level or Add Level and save that level’s fields. New caller level and Sysop threshold, and the message body limit, retain their separate save scopes; changing the selected level does not silently submit them. See editing and save results.

A security level is a shared definition used by callers assigned to that number. Editing a level changes that definition; it does not select one caller for editing. A fresh board contains level 10, New User, and level 999, Sysop. Normal updates retain your configured levels and their saved limits.

FieldRulesStarting value
Level numberWhole number 1-999. Choose an unused number for a new level. Removed numbers cannot be reused.Windows New Level starts blank; Linux Add starts at 1. These are drafts until saved.
Label1-32 printable ASCII characters, with no leading or trailing spaces.New User for 10; Sysop for 999. A new level needs a label.
DescriptionOptional, up to 128 printable ASCII characters. Leave empty or use text without leading/trailing spaces.Empty.
Minutes Per Call0-4,294,967,295 whole minutes; 0 means unlimited. Level 999 must remain unlimited.180 for fresh level 10; unlimited for 999 and a new level draft.
Minutes Per DayThe same range. Total caller time available in a BBS-local calendar day; 0 means unlimited. Level 999 remains unlimited.180 for fresh level 10; unlimited for 999 and a new level draft.
Minutes Per Private ChatThe same range, per private conversation; 0 means unlimited. Linux labels this Private chat minutes per call.Unlimited.
Private Chat Minutes Per DayThe same range, for accumulated private-chat time that day; 0 means unlimited.Unlimited.
New User level / New caller security levelAn active configured level, 1-999, assigned to newly registered callers. Existing callers keep their assigned levels.10.
Sysop threshold / Sysop security thresholdAn active configured level, 1-999. Callers at or above it have Sysop authority, subject to Sysop authentication.999.

The 180-minute fresh level-10 limits are not imposed retroactively on an older completed installation whose calling allowances were unconfigured: that upgrade case retains unlimited allowances. Check the displayed values after an upgrade. For a new regular-caller level, for example, choose an unused number such as 20, label it Regular, and set a per-call allowance of 60 and a daily allowance of 120. The caller can use at most the time remaining under both limits. Daily time follows the BBS time zone.

Save a level or shared defaults

On Windows, select a level or choose New Level, fill in its fields and choose Save. Review the shared New User level and Sysop threshold too: the Windows save review includes them. On Linux, select a level or Add, then save; use the separate New caller level and Sysop threshold entry to save those shared defaults.

These changes do not require a BBS restart. Reduced access and time allowances apply to online callers. Newly granted Sysop access requires a fresh login and System Password authentication; merely changing a level is not a way to turn an ordinary live session into an authenticated Sysop session. Level 999 has unlimited calling time and may have simultaneous sessions; the Sysop threshold does not give those two special level-999 privileges to other levels. Authenticated Sysops are exempt from caller AFK as described under Caller Idle Limits.

Private-chat limits are separate from ordinary calling time. A conversation can end when either participant exhausts an applicable private-chat allowance. A zero in one field removes only that field's limit. It does not bypass the other participant's limits or the rest of the board's access policy.

The selected level also has a separate message body-line limit. Save Message Limit changes that limit separately from the calling-time and security fields.

Remove a level

Choose Remove Level... on Windows, or the selected level's remove action on Linux. Review the affected callers and choose another active level for reassignment. A shared default that used the removed level moves to the chosen replacement too. Removal permanently retires the number; it is not an undoable rename. The operation refuses an outdated review or a change that violates last-usable-Sysop protection. If the caller list or policy changed, reload and review again.

If a normal Save is refused, check the level number, label and description, whole-minute limits and active shared defaults. A removed level cannot be restored by saving its number again. If a result says the database change committed but publication needs recovery, do not repeat the change; reopen SFXConfig and follow the recovery message.

Users & Access > New User Registration

Linux SFXConfig: Change the registration choice and use Save Changes. Read its actual saved/active result; it does not create accounts or change existing callers’ assigned levels. See editing and save results.

Allow New Users on Windows, or Allow new callers to register on Linux, controls whether a new caller may create an account. It is an on/off choice and starts on for a fresh board. Turning it off does not itself block existing accounts from logging in; their normal account and security checks still apply.

Save the change and read the result. When a running BBS reports Applied, new connections use the changed setting. Callers already at a login prompt keep the settings from when they connected. If the BBS is stopped, the saved setting is used when it starts. If other changes were saved too, follow the actual Applied, Pending or Restart-required result.

For a private board, turn registration off while keeping established callers' access. To accept new callers again, turn it on and verify Applied before testing a new connection. Choose the New User level separately in Security Levels; this checkbox does not assign a level or grant Sysop access.

A normal update preserves an existing saved choice. Very old configuration formats that have no registration choice load with registration enabled, so check this setting after converting an old board. If a caller still sees the old choice, reconnect before testing again. If Save reports a revision conflict, reload the saved settings before retrying.

Users & Access > Caller Password Policy

Linux SFXConfig: Choose the caller-password rule and use Save Changes. Follow the required BBS restart and check the active policy; this does not replace the permanent System Password or rewrite existing caller credentials. See editing and save results.

Require Strong Passwords on Windows, or Require strong caller passwords on Linux, chooses the rules for newly set caller passwords. It starts off (Standard). An update preserves your saved policy and existing credentials.

ChoiceRules
Off: Standard4-128 printable ASCII characters, including spaces.
On: Strong15-128 printable ASCII characters, checked against the packaged local blocklist and account/board context.

Strong does not require a particular mixture of capitals, digits and symbols. It rejects complete passwords found in the blocklist without regard to case, and simple forms derived from the account name, BBS name, Spitfire or SFX. Adding a few digits to a name is not a way around the context check. Choose an unrelated phrase within the allowed length; do not reuse a documentation example as a real password.

On Windows, choose Save Changes; on Linux, save the page. A policy change requires a BBS restart. It does not replace or invalidate existing passwords, or force all callers to change them. After restarting, check the active policy before relying on it for new passwords.

If a new password is refused, check its length, printable characters and the stated policy reason. Strong needs its packaged blocklist; unavailable blocklist data is a failure, not permission to skip the check. SFX uses the local data and does not download a list during password entry. The separate System Password protects Sysop access and management; changing caller policy does not replace that password.

Caller Change Password

Two consecutive empty Enter entries at Current password return the caller to Your Settings. To change the password, enter the current password and follow the new-password prompts and active policy. This caller action is separate from the Sysop Reset Password action.

Connections > Caller Idle Limits

Linux SFXConfig: Keep the minute and second units distinct, then Save Changes. Applied limits are for new calls; an existing call can retain its captured interval. See editing and save results.

Idle limits release a connection when the caller stops entering commands. They are different from the total calling-time allowances in Security Levels. Updates keep the saved idle choices.

SettingStarting valueAllowed values
Caller AFK / Caller idle limit5 minutesWhole minutes from 2 to 1440. Applies after authentication; authenticated Sysops are exempt.
Login idle / Login idle limit60 secondsWhole seconds from 30 to 600. Bounds idle login input before authentication.

For example, a caller idle limit of 10 means ten minutes, while a login idle limit of 120 means two minutes. Zero does not disable either limit. Caller keyboard input resets the post-login idle timer; output, redraws and transport traffic do not. Windows provides a warning one minute before disconnection.

Linux idle-warning limitation Do not rely on a visible warning before the idle cutoff. The cutoff and authenticated-Sysop exemption still apply.

On Windows, choose Save Idle Settings; on Linux, save the page. An idle-only change can apply without restarting the BBS. Applied settings are used for new calls; a caller who is already authenticated keeps the idle interval assigned to that session. A login already in progress keeps its captured login limit. Windows takes the post-login interval when authentication completes, while Linux keeps the interval captured when the call began.

Read the Save result before retrying. On Windows, Retry Idle Settings reloads the page's connection and settings context while retaining an unsaved draft for review; use Save Idle Settings to submit it. If a value is refused, check its units and range. To check a changed limit, start a new ordinary caller connection after Applied; an authenticated Sysop session is exempt from caller AFK and is not a suitable check of that timeout.

Chat > Chat Rooms

Linux SFXConfig: Select a named room or use Add Room, edit its grouped fields, then Save Changes. These are room settings; the separate chat controls send messages. Existing occupied-room and entry-room protections still apply. See editing and save results.

A fresh board has one enabled entry room named Lobby, using a minimum security level of 10 with Sysop Only off. Updates keep the saved room list. You can define up to 128 rooms; the entry room must stay enabled and cannot be deleted.

FieldRules and starting choice for Add
Room nameRequired text, up to 64 bytes; plain ASCII allows 64 characters. No control characters or line breaks. Add starts with an empty name.
Enabled / Enable this roomStarts on. Off hides the room from callers. This choice cannot be turned off for the entry room.
Access Requirements / Security level ruleMinimum (at least), maximum (at most), or exact level. Starts at minimum.
Security levelWhole number 1-999; starts at 10. For example, minimum 20 allows callers at level 20 and above.
Sysop OnlyStarts off. On uses the BBS Sysop threshold instead of the numeric minimum/maximum/exact rule, and requires authenticated Sysop access.

On Windows, choose Add Room or select a room and choose Edit Room, then Save Changes. Cancel / Reload returns to the saved settings. Linux offers the same fields through its room selection and Add flow. For example, create Regulars with minimum level 20, or turn on Sysop Only for a private operator room.

A room must be empty when you save a change or delete it. SFX refuses a change to an occupied room; it does not move callers out to make the edit fit. A successful save applies without a BBS restart. If another session changed the room list, reload and review the current list before saving again.

Delete Room removes the selected empty room and cannot be undone. The entry room is protected. If Save is refused, check the name, level range, room count, occupied-room status and the saved revision.
