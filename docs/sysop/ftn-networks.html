Connect to FTN networks

Set up your network, choose the echoes your callers can use, and exchange mail with your hub.

Open SFXConfig > FTN Networking > Networks. On Linux, open Configuration > FTN Networking in the browser controls. You need the address assigned to your board and the connection details supplied by your network or hub. A preset does not assign an address or arrange membership.

These controls describe the 1.0.0b2 test build. See the External BinkD guide for the included optional Windows companion and Linux helper. Existing saved choices stay in place when you update. The defaults below apply to a new entry, and the guided setup differences are called out separately.

Save, drafts and activation

On Windows, use Save Changes on the page you are editing. During guided setup, Keep in Setup Draft and Apply to Draft retain your choices until the final Save Network. Save and Finish Later saves an unfinished network disabled.

On Linux, Apply to Draft keeps the current form in your unpublished FTN draft. Use Save FTN Settings to publish that draft. The browser keeps ordinary entries for the same tab where possible; password replacements are cleared when you leave or reload the form. Re-enter a replacement if the page asks for it. A draft is not a backup and is not shared with another browser session.

If settings changed elsewhere, reload and review the saved version before trying again. If a save result is unconfirmed, use Check Save Result to recover that exact save before starting another save or import. Reload and Discard have different purposes: read their prompt before abandoning unsaved choices.

Settings saved with the BBS stopped are used at the next start. With the BBS running, a successful save asks the mailer to activate the new configuration, including listener addresses/ports/TLS and network, connection, echo and routing policy. No full BBS restart is needed. Current mail sessions and processing are stopped and joined before the replacement configuration starts; an active backup hold delays this change. Check BinkP status afterward: saving and activation are separate, and a saved port or certificate does not prove that the listener opened successfully.

Remove Network removes its FTN connections, mappings, routes and permissions. Remove Connection also removes dependent routes and permissions and clears its default-hub or upstream-provider use. Remove Mapping removes the FTN association. These actions preserve local conferences, messages, file areas, files and retained spool data. Review the named item before confirming.

External BinkD

Read setup and daily use and the supported profile reference for this build.

In External mode, saved Native endpoints and contact/timer values remain preserved but do not control BinkD. Scan Outbound requests SFX processing; Poll is unavailable because BinkD owns calling. Handed to BinkD does not mean Delivered. Stop both programs before a consistent backup, restore or mailer change. Managed-original expiry remains separate from retained raw BinkD copies and history.

Network settings

Linux SFXConfig: Choose the network, then its named task and records. Apply to Draft keeps the current task unpublished; Save FTN Settings is the final save for that draft. The network setup, imports, held mail and recovery tools keep their own reviews. See editing and save results.

Select a network and open Network Settings. A new ordinary Add entry starts disabled. On Windows it is named “New Network” and its Origin starts with the BBS name; Linux's ordinary new form starts with those text fields blank. The guided setup has its own starting choices.

Set Up a Network

The nine-step setup keeps one draft until you finish. Start with FidoNet, fsxNet or Other and replace the proposed facts with your own. New setup proposes Enable this network after saving, Receive and Send On, and no AreaFix request. Cancel Setup discards the unsaved setup while preserving saved networks and mail.

  1. Network and message group: enter the name, assigned address and existing or new group. Setup begins with FidoNet and a FidoNet group name. Matching an existing group preserves its settings.
  2. Your hub connection: supply the hub name, address, host and port (initially 24554), or choose to add it later. Session, packet, AreaFix and TIC passwords are separate. A new setup hub is enabled for incoming and outgoing mail, contacts when mail is queued, and has its timer off.
  3. Choose message echoes: load a local list or explicit HTTP/HTTPS URL, or add tags manually. A caller name is optional only when the tag itself fits the 64-byte local name limit. On Windows, new list entries in this guided step start unchecked; the separate Import Echo List page starts usable entries checked. Linux setup uses that separate import review. Check the selected count before proceeding.
  4. Caller access: select an echo and set its caller-facing name and Access, Read and Post levels. New levels are 10, range 1–999. Apply to All copies the levels; caller names remain individual.
  5. Echo exchange: choose Receive and Send for the selected hub. Prepare an AreaFix subscription request starts Off and only prepares it. Queueing later needs an enabled network and hub, the separate AreaFix password, at least one selected echo, and Receive permission.
  6. NetMail and contact policy: review the chosen hub. Contact when outgoing mail is queued starts On for a new setup hub. The optional timer starts Off; if enabled, its proposed 30 minutes can be changed to 1–65535.
  7. Names, colors and Origin: review each echo or explicitly apply choices to all. New echoes require Real Name for FidoNet, otherwise Off; outgoing ANSI and pipe colors start Off. Review the Origin rather than assuming a preset is your final text.
  8. Optional features and message limits: .MSG scanning starts Off and the nodelist path is blank. New FTN echoes keep 500 messages with unlimited age. Change the selected echo or explicitly apply to all.
  9. Review and Save: inspect the hub, group, each echo's limits and permissions, optional features and Enable choice. Save Network saves without generating a subscription request. Save & Queue AreaFix Request is the separate action that saves and queues the prepared request. Queueing is not proof that the hub received or accepted it.

Review Network Setup lets you review an existing network. On Linux, differing saved Receive/Send permissions remain until you deliberately change those choices; changing either applies both visible choices across the setup's message echoes. Use full settings for larger or more specialized configurations. Linux setup and bulk-option selections are limited to 4,096 echoes; local conferences still share the BBS-wide 999-conference capacity.

Connections and passwords

A connection is a particular system in one network. Its network and its own Enabled choice must both allow activity. New ordinary connections start disabled, with blank identity/host fields, incoming and outgoing use, port 24554, a 30-minute timer, and Contact when mail is ready Off. Guided hub setup changes those last choices as described above.

Direct NetMail without a session password

Native BinkP on Windows and Linux can receive direct local NetMail when no session password is expected. For an unconfigured sender, Allow direct local NetMail from unconfigured systems must be on. The packet must name a unique enabled local recipient. A successful no-password connection does not verify the sender or grant message-echo, relay or queued-mail pickup rights.

If a connection has a saved session password, that password still has to pass its normal checks. An unreadable saved password is a failure, not permission to receive anonymously. Packet passwords and AreaFix passwords keep their separate purposes and permissions below.

Four separate passwords

Session protects the BinkP session; Packet protects message packets; AreaFix authorizes echo-management requests; TIC protects file-echo control files. All start unset. Packet passwords allow at most 8 printable ASCII characters; the other three allow 128. Spaces count. Use the values agreed with the remote Sysop.

Leave an untouched saved password alone to preserve it. Enter a replacement to change it, or explicitly choose Remove current / Remove this saved password. Clearing a displayed password field is not a reliable substitute for that remove action. SFX protects saved credentials; a “cannot read” status is not evidence that the saved value is blank. After a failed or interrupted browser edit, re-enter any intended replacement and check the save result.

Import an EchoList

Open Import Echo List from Message Echoes. Choose a local .NA text file on the BBS computer or an explicit HTTP/HTTPS URL, then Load List. Opening the page does not fetch, import or subscribe. On Windows, Skip for now leaves you free to finish without an import.

A list is at most 4 MiB, 50,000 lines and 4,096 bytes per line. Each usable line is an echo tag followed by its optional description; blank lines and lines starting with # or ; are ignored. Invalid and duplicate lines are reported. Choose UTF-8 / ASCII or DOS CP437 to match the file. The Windows guided setup automatically falls back to CP437 for a non-UTF-8 list; the separate import page and Linux expose the encoding choice.

Linux accepts a full file path or a path relative to the BBS root. Its load field permits 4,096 bytes, but the saved network file-path field is limited to 1,024; choose a source that fits the saved setting. Windows offers Browse; its guided setup resolves relative files from the BBS root. Use Browse or a full path on the ordinary Windows import page. HTTP/HTTPS URLs have the 2,048-byte limit described above. A failed or cancelled load preserves the prior reviewed list and draft.

  1. Review rejected lines and the usable count. The separate import page starts usable entries selected; Clear All and choose only the echoes you want. Find filters the display, so check the total selected count across pages.
  2. Set new-conference Access, Read and Post levels, initially 10, each 1–999. Windows offers Set Requirements for Checked Entries; Linux uses the displayed levels for the selected import. Existing saved conference requirements remain.
  3. Leave Update selected existing names and descriptions Off to preserve them. Turning it on updates text only for selected existing mappings. Entries missing from the list are not deleted.
  4. Review the destination group and counts of new, unchanged and text-updated echoes. Existing mappings across incompatible groups, conflicting local names or insufficient free conference slots must be corrected before importing. There are at most 999 local conferences across the BBS; an over-capacity import is refused as a whole.
  5. On Windows, the ordinary Review / Apply Selected action saves the confirmed import; inside setup it retains it in the setup draft. On Linux, Apply to Draft still requires Save FTN Settings. No import action automatically queues an AreaFix subscription.

New imported local echoes start with 500 messages, unlimited age, outgoing ANSI and pipe colors Off, and the FidoNet real-name choice described above. A tag longer than 64 bytes needs a shorter local name in the normal echo editor. If the save is uncertain, use Check Save Result rather than importing again.

Clone Options

Use Clone Options in Message Echoes or the final setup review to apply selected values across named echoes in this network. It does not duplicate messages or create another network.

All five copy switches start unchecked: Message count, Age limit, Access, Read and Post. Proposed values are 500, Unlimited, 10, 10 and 10. Check only the fields you intend to change, then select targets, use Preview, and Apply to Draft. All Echoes in this Network selects targets across pages; Clear Targets removes that selection. Linux accepts at most 4,096 selected targets per operation.

Use the same count, age and security-level ranges as the echo editor. Unchecked fields, names, colors, real-name policy, subscriptions and message contents stay unchanged. Apply to Draft is not the final save. Save the reviewed FTN draft afterward; changed limits are used by later message retention.

File echoes

Create the destination under Files > Groups & Areas first, then Add File Echo inside the network. Enter the file echo tag (the same 1–128-character rules as message tags), an optional description up to 512 UTF-8 bytes, and an existing ordinary local file area. A new entry has no destination selected. Private upload/review areas are not ordinary file-echo destinations.

Give the appropriate connection explicit file-echo Receive and Send permissions. TIC import requires an authorized configured link. If no TIC password is set, the received file still needs authenticated receipt from that same link. Save the mapping and permissions, then inspect BinkP status or Held Mail if a file does not arrive. Remove Mapping preserves the local area and its files.

Connection echo permissions

Open Echo Access Exceptions / Connection Echo Permissions for the connection. Select named message or file echoes, then choose Receive, Send and, for message echoes only, AreaFix management. Apply to Selected on Windows or Apply to Draft on Linux changes the selected rows in the draft; finish with the normal save.

Receive permits mail from that link into the named echo. Send permits distribution to that link. AreaFix management lets the link add or drop its own Send subscription using its separate AreaFix password; it does not change Receive permission. Clearing management prevents those remote changes. Secure Operation remains On.

An echo without a permission row grants no access. The selection controls start unchecked; inspect each row's current permissions before applying a batch. Selecting a connection, adding a password or enabling AreaFix does not itself grant every echo. Normal hub setup can create the explicitly listed Receive/Send rows described above. File echoes cannot have AreaFix management.

Routing and polling

Choose a Default NetMail hub when NetMail should go through your hub unless a specific route or configured direct connection applies. None is the new-network default. A selected default must be an outgoing connection in this network and must be enabled when the network is enabled.

Add Route takes one exact Destination FTN address, an outgoing Send via connection in this network, and a Mail policy: Normal (new-route default), Hold or Crash. The address uses the format above; it is not a wildcard pattern. Review the actual destination and connection before saving.

Normal follows ordinary dispatch. Hold is excluded from automatic outgoing batches and contact-on-mail readiness. Crash marks the route's outgoing mail with the Crash flavor; it is not a promise of immediate delivery. Connection availability, authentication and retry state still matter. Poll interval and Contact when mail is ready are separate controls on each connection. Poll Now is a runtime action, not a saved schedule.

If mail does not move, check the network and connection Enabled choices, connection direction, endpoint, current passwords, route/default hub, echo permissions and the BinkP or Held Mail reason. Do not repeatedly import the same echo list to fix a connection failure.

Keep processed originals

Each new network starts with Keep processed incoming originals On and 30 days. Days accepts 0–65535, with 0 meaning Forever. Turning Keep Off affects future successful processing; it does not immediately remove all existing retained originals.

When a shorter period would shorten protection for existing processed originals, Save opens a review. It shows each affected network, originals due now, those expiring later, those previously kept Forever, and the new expiry-date range in the BBS time zone. Confirm only after reviewing those counts. Cancel leaves the saved settings and protection dates unchanged and keeps your edits unsaved.

The confirmed save applies the exact reviewed originals and the other settings together. Later arrivals are not silently added to that review. Originals still needed for processing, forwarding or recovery remain held. Imported messages and published files remain; their own retention and file-area settings are separate.

Message ID history recovery

A saved message-ID history hold is separate from an individual item in Held Mail. A healthy complete-folder move or coherent older restore is not, by itself, a reason to keep FTN disabled. Keep other copies using the same FTN addresses stopped and follow the normal copy/restore result.

If SFX specifically reports that message ID history needs recovery, stop the BBS and any independently launched BinkD, then use Recover FTN History in Backup & Restore. The guided action verifies required queued files, preserves existing messages/IDs and known completed work, and leaves separate item holds unchanged. It does not require an empty queue or repair missing/changed originals.

Held Mail

Held Mail reads saved mail state, separately from an unpublished FTN settings draft. Use the network, exact reason and Find filters, then Find / Reload. Select an original and open Details. An unavailable list is not an empty queue.

Details show the original, sender/network/connection where recorded, current reason and the last reviewed retry. For message packets, choose the specific constituent message to inspect its From, original To, destination and intended echo. For TIC files, inspect the claimed From, echo, payload, publication stage and retained forwarding plan.

  1. Correct the relevant saved connection password, echo mapping, permission or destination first. Reload Details after the correction.
  2. For an unresolved local private recipient, choose the specific uncommitted message, search active local callers and explicitly select the intended account. Review and save that recipient choice. The original To and packet bytes remain unchanged; already committed messages cannot be reassigned.
  3. Use Reprocess Original as a separate reviewed action. It checks the current credentials, permissions, mapping, retained original and any recipient decision again. Already committed messages are not delivered twice.
  4. Reload Details to read the result. A queued retry is not successful processing. With the BBS stopped, a reviewed retry waits for the next enabled start. Changed/missing files, an absent original forwarding plan or a disabled mailer can still prevent processing.

For an interrupted TIC publication, reprocessing reviews that exact original and its recovery/forwarding plan; it cannot manufacture a missing plan or repair changed payload bytes. Do not delete the original to clear the display. If an action result is unconfirmed, choose Check Action Result to reconcile the same action before attempting another one.
