Linux browser controls

Open your controls, change settings and try a caller session.

v1.0.0b1 test buildThis guide covers the Linux 1.0.0b1 browser Control Panel and SFXConfig. Install the new lowercase layout separately from older uppercase boards.

Fresh install on the Linux desktop

For a new board, use a terminal opened on the Linux desktop where SFX will run. Install as your normal account into a new, empty folder you own. Existing lowercase boards use the upgrade steps; older uppercase boards and backups are not converted.

Download the single Linux .tar.gz, extract it once, and enter its versioned folder. For this release:

tar -xzf spitfire-x-1.0.0b1-rc2-linux-x86_64-20261124-r1.tar.gz
cd spitfire-x-1.0.0b1-linux-x86_64
python3 install.py

Staging and installation are different folders. The extracted versioned folder contains install.py and payload/. Run the installer there, then choose the separate folder that will hold your board, for example $HOME/sfx. The fresh destination must be new or empty. Do not select the extracted package folder or a parent that contains it.

The installer asks for a full destination path and confirmation. Enter accepts the shown ~/sfx default. The parent folder must exist; run without sudo. An explicit --prefix "$HOME/sfx" selects a destination without prompting. See runtime and desktop requirements.

Installation prints the exact launcher command for your selected folder. Run it in that Linux desktop terminal; for the default folder:

"$HOME/sfx/spitfire-x"

If a fresh destination is nonempty or contains the extracted package, select another empty folder you own. If it is an existing SFX board, use the upgrade flow. Preserve both sets of files while reviewing the paths. A permissions refusal identifies the exact ownership or group/other-writable path; correct only the intended private location or choose another one. Do not run the installer as root or change an unrelated parent tree to force acceptance.

It opens or reuses the local Control Panel in your desktop browser. A fresh installation has no board database or account. In Set Up Your BBS, enter the BBS name, time zone, number of nodes, listen address and caller ports. The defaults are Telnet 2323 and SSH 2222; choose unused ports. Enter the Sysop name and caller password, then the separate permanent System Password. Repeat both passwords. Require strong caller passwords remains a separate checkbox.

Choose Create My BBS, review the saved settings, then choose Start BBS when ready. Installing, creating the board or opening the controls leaves callers stopped. If the result is unclear, use Check Setup Result before another attempt; keep the same Sysop name and passwords when resuming interrupted setup. An existing board is not replaced by this flow.

Use the separate SSH access steps when connecting from another computer; a terminal opened on the Linux desktop follows the ordinary desktop flow above.

Know the Linux folders

The launcher is spitfire-x; the starting guide is readme.txt. SFX-owned live paths use lowercase, including folders created later under bin, config, data, display, doors, botgate, docs, ftn, files, backup, logs, web, work, management, node and games. Core files include config/sfx.conf and data/sfx.db. Fresh file areas use files/general, files/uploads and files/uploadtosysop.

Required DOS/game names, original vendor-relative files and IANA time-zone names keep their required case. SFX does not rename an arbitrary existing path you select, an uploaded filename or supplied game/artwork files. The outer installation folder remains the one you chose.

config/linux-layout.v1 identifies this layout schema; the protected receipt also records it. It is not a board identity or a repair switch. A copied lowercase board keeps the marker and may still need normal copied-file preparation. Do not create or edit the marker to bypass a refusal.

Open the controls

Use the local launcher on the Linux desktop to open the browser controls. It handles local access without asking for the System Password. Reopen through the launcher if local access expires. You need a usable desktop and browser for this local route; see Linux prerequisites before planning an installation.

Choose Control Panel to see BBS status and callers, or SFXConfig to change settings. Open SFXConfig also takes you there. Opening or closing the browser leaves the BBS running or stopped as it was.

If the desktop browser does not open, read the private browser-launch diagnostic and local-link steps.

If the desktop browser does not open

Read the launcher result. Desktop xdg-open diagnostics go to the installed board's private management/browser-launch.log. A genuine launch failure names that log and offers the local spitfire-x --print-url route. Use the exact installed path, for example "$HOME/sfx/spitfire-x" --print-url, then open the full printed link in a browser on that same computer.

The link contains temporary local access. Keep it and the browser-launch log private; redact sensitive information before asking for help. Browser output alone is not evidence of an SFX integrity or antivirus problem. For a host reached by SSH from another computer, follow the separate forwarding instructions below; remote loopback does not point at your local browser.

Use a browser through an SSH connection

This optional route needs an existing operating-system SSH login for the SFX owner account and permission to forward ports. The Linux host needs no desktop browser for --print-url; use the browser on your other computer. This route does not use the BBS caller SSH port or install an SSH service. Install or upgrade on the Linux host first, then run this in that SSH shell with your actual installation path:

"$HOME/sfx/spitfire-x" --print-url

Keep the full printed http://127.0.0.1:PORT/#launch=... link private. On the computer running your browser, open another terminal and forward the same numeric port through your normal host SSH connection. For a printed port of 39123:

ssh -N -L 127.0.0.1:39123:127.0.0.1:39123 yourname@linux-host

Replace both example ports with the actual printed port, and replace the account/host. Keep the tunnel terminal open and bind only its local 127.0.0.1 address. Resolve a busy local port or a forwarding refusal instead of exposing the listener or weakening authentication.

Open the complete printed link in your browser on that computer, retaining its loopback address, port and entire token. A new board uses the same setup/review/Start BBS sequence above; an existing board keeps its setup. If the link expires before use, rerun --print-url and use the new complete link.

Closing the tunnel ends this browser route, not the BBS or management. Use their normal stop controls when needed. LAN HTTPS access is a separate post-setup option with its approved addresses, certificate and System Password.

Use another computer on your LAN

Linux SFXConfig: Review the listener, approved computers and certificate/session choices in their separate groups. Save Changes can end LAN browser access; retain access through the trusted local launcher and verify the current certificate fingerprint. See editing and save results.

In Security > Web Access, LAN access is off on a fresh board. It needs a listening IP on the Linux computer, a free HTTPS port, exact Approved IP addresses and the existing SFX System Password. An approved IP alone does not sign you in. Save, then refresh the page and check the listener status.

Before the first LAN sign-in, compare the certificate's SHA-256 fingerprint with the one shown through trusted local access. A certificate created by SFX is not automatically trusted by your browser. Do not disable certificate checks or accept a warning without verification.

Turning LAN access off or removing an approved IP leaves local launcher access available. Changing the System Password ends old LAN authorization. From local access, End all LAN browser sessions on Save ends remote sessions without stopping BBS callers.

Edit and check the result

In SFXConfig, expand a group and choose its page. Start with the named item you want to change: a caller, security level, group, area, room, network or job. Check the selected name and parent before editing. The selected item determines the actions shown beneath the list or tree.

On a settings page, change the fields in its named groups. For a listed item, select it and use its offered action. Save Changes saves the current editor; Discard Changes drops its unsaved edits. Creating an item uses the named finish action. Leaving unsaved edits offers Save, Discard or Stay, subject to pending or uncertain work. Discard never undoes an earlier confirmed save.

In the Messages and Files browsers, selecting another row changes the available actions while an existing editor can stay open. Check its Editing name before Save Changes. Use the intended Edit action to open another item; the list selection is not a command to save a different record.

A page can contain several independent settings or tools. QWK, System Sysop, statistics, message limits, scan policy, event-sound assignments and maintenance actions keep their own controls and results. Saving the main editor does not silently save those other changes. Some pages offer actions or reports without an ordinary settings editor.

Read both the saved result and the active state. A saved node count or password policy can need a restart; new idle limits apply to new calls, while existing calls keep captured limits. Saving a listener or network does not prove that it started successfully. Follow the page's actual result instead of saving repeatedly to force activation.

If a reply is missing, SFX may already have saved the change. Use the offered Check Save Result, saved-settings review or same-operation recovery before another write. Keep the selected item and tracked operation. A confirmed save followed by a failed refresh is different from an unknown save outcome. Never create another item just to replace an unconfirmed one.

Password replacements are cleared rather than kept in ordinary drafts. Re-enter a replacement only when the specific recovery flow asks for it; a stored-password indicator or changed revision does not prove which value was saved. Caller passwords, the permanent System Password, FTN session passwords and remote-Door credentials have different purposes.

Paths refer to the Linux BBS computer. A Windows workstation's file picker cannot select a Linux-host folder. Read the existing folder, ownership and stopped-board requirements before using a program, certificate, WAV file or restore point.

Help callers

Select the current node, then choose Edit Caller to open that caller's Accounts record. Save or discard any existing settings draft first.

Choose Notice to Caller or Send System Notice for the selected caller, All Callers or a configured chat room. Choose Review Notice, check the recipients and text, then Send Reviewed Notice. Cancel or Close leaves an unsent notice unsent. If the result is uncertain, use Check Send Result; it never automatically sends again. Overriding Do Not Disturb (DND) needs a separate, explicit review for that notice only.

Use Mark Available for Chat or Mark Unavailable for Chat to control caller pages. Answer Page keeps normal calling time; Chat with Caller pauses calling time. Both ask for consent before starting the conversation.

Chat stays visible when you open SFXConfig. Use Send, Check Chat and End Chat. Private chat history is not saved. If you close the operator browser or it stops responding, chat ends after ten seconds. The caller stays connected to the BBS.

Try a browser caller session

With the BBS running, choose Logon for the wanted node showing Waiting for caller with Logon enabled. If it becomes unavailable, check node status and choose another available node or wait. Sign in with your ordinary caller account; management access is not a caller or Sysop login.

Click the terminal screen to type. It supports ANSI colors and CP437 characters, with Enter, Escape and Backspace buttons. Ctrl-X passes through to Telnet Gate. The optional Send a line (hidden while typing) field and Send and Enter send a line together.

Input is not saved or automatically replayed. If sending it has an uncertain result, use Refresh Terminal and read the screen before typing more. Disconnect ends only this terminal and caller. If the page stops checking the terminal for 15 seconds, only that browser caller is disconnected.

Use an optional desktop client

Linux SFXConfig: Use the profile’s own save and launch controls. The executable and arguments belong to the Linux BBS computer, even when you are viewing SFXConfig from another computer. Saving a profile does not start the client or the BBS. See editing and save results.

For a desktop BBS client on the Linux computer, use Connections > External Client. Choose None, SyncTERM or Custom and the full installed program path. Save Client saves the profile; it never launches a program or starts the BBS. Clear / Reset saves an empty profile without deleting the client.

After reviewing the saved profile, use the local page's Use at the Linux desktop command from a terminal on that desktop, under the account that owns the SFX folder. Keep its path quoting and change the final node number to your chosen available node. Management and the BBS must already be running. Browser Logon still opens the built-in terminal. Use a desktop client for file transfers; the browser terminal is not a ZMODEM client.

Keep BBS startup separate

Linux SFXConfig: Review the Linux hosting status and save the Start BBS when Linux starts preference separately from starting or stopping the BBS. Saving the preference is not service installation or an immediate BBS start. See editing and save results.

Management starting with Linux and the BBS starting automatically are separate choices. Under System > Runtime Behavior, Start BBS when Linux starts is off on a fresh board and is used when the Linux service starts. Saving it does not start or stop the current BBS. The local launcher never starts the BBS for you.

Use Start BBS when you want callers to connect. Stop BBS asks for confirmation with the actual caller count when callers are online; with no callers, it stops directly. Stopping the BBS leaves management available.

Start management with Linux

First Stop BBS, finish active work and close foreground management. Then prepare a service plan with the installed commands, using your actual installation folder:

"$HOME/sfx/spitfire-x" --stop-management
"$HOME/sfx/prepare-sfx" --service-plan

If callers need ports below 1024, add --low-ports after --service-plan. SFX still runs as your normal account; helpers and Doors do not inherit permission to bind those ports.

This creates a service file and prints administrator commands; it does not register the service. Have an administrator review the file, then use the printed install, daemon-reload and enable--now commands. Use the exact account, service name and path from the current plan.

Repeating an identical private plan is safe. Changed or edited plans are kept, with the new plan in a separate private subfolder using the same service filename. Use the path printed by the current run. After moving SFX or changing accounts, retire the old service registration and prepare a new plan. Start BBS when Linux starts remains a separate SFXConfig setting, off by default.

Read activity and statistics

Events and Live Logs are read-only views. In Live Logs, use Show to filter the source and Pause or Resume to control the displayed stream. Clear View clears the display, not the log files. A gap, restart or unavailable notice means some observations cannot be shown; an unavailable value is not zero.

Statistics shows saved Today and Total logon, time and new-user totals. Today follows the BBS time zone. The separately labelled Runtime counters cover the current management Runtime and can reset when it restarts.

In BotGate Status, compare the saved participation setting with current readiness, recording and feed status, counts and recent activity. An enabled setting does not mean a stopped BBS is screening callers. Use Open BBS Security Settings to reach the existing settings.

Follow FTN mail

BinkP Console shows sessions, queues and activity. Select a session or follow the active one. Poll Now... and Scan Outbound... require an in-page review before dispatch. Check Action Result reads the outcome without sending the action again. Queued mail is not delivered mail; delivery needs the peer's acknowledgement.

Queues / Held Mail, Review Held Mail... and FTN Settings open separate views. Configured peer and endpoint labels describe current settings, not a past connection's socket. Stopped live readings show Not running. External BinkD is included in the beta.8 test package; see the setup guide. Its reviewed browser status says Ready for External BinkD, with Scan available and Poll unavailable.

Watch the Linux server

System Monitor has six cards for the Linux server's CPU and per-core activity, memory, physical disks, SQLite activity, network interfaces other than loopback, and uptime. These readings come from the server, not the computer running your browser. Missing or first readings show unavailable or waiting for a sample.

Pause Monitor, Resume Monitor, Refresh Monitor and Close Monitor control this view. Grayscale graphs and Compact layout change its appearance. Graphs keep up to 60 recent samples while the view is open; expand per-core activity for individual CPUs.

OS uptime measures how long Linux has been running. BBS uptime starts over when SFX stops and restarts. SQLite activity covers the shared Runtime connection's database pages, not every program on the server.

Manage files and queue Hatch mail

Open File Manager on the Control Panel. Use Browse Groups or Search Filenames to find cataloged files. View Details and ZIP Contents show information and archive member text; they do not run a Door or extract files.

Rename..., Move... and Remove... each require an in-page review. Multiple removals list the selected files, run in order and stop on uncertainty or failure. Cancel does not undo completed work. Search Pending Files... and Search Offline Files... run scans that can update the catalog. Read Current File Job and use Check Job Status before retrying an unclear result.

Review Unfinished Work returns to the original operation, import, intake or Hatch for review and recovery. Keep using that request instead of starting another operation over uncertain files. Held work is not completed work; the original and whatever work was made are kept for review.

Hatch File... verifies the selected file before offering permitted FTN network, file echo, origin and destinations, plus an outgoing description. Review Hatch Queue... confirms those choices. The original file and catalog stay unchanged. Queued does not mean delivered or accepted. This description is for outgoing Hatch mail; editing general catalog descriptions is not available yet.

Use browser event sounds

Event Sounds starts off in each Control Panel browser tab. Choose Enable Sounds in This Tab to play new events through that browser. Only one tab receives the live sound stream. Closing it, disabling sounds, signing out or switching to SFXConfig stops playback. Allow browser audio and use a working audio device; playback does not use the Linux server's speakers.

Edit Event Sounds opens ten assignments. Enter full WAV paths on the Linux BBS computer, not your browser's computer. Blank means silent. Use local files owned by the BBS account: PCM WAV, 8/16-bit mono or stereo, 8-48 kHz, at most 30 seconds and 2 MiB.

Each path is at most 768 UTF-8 bytes and ends in .wav. Use an absolute path without links, empty components, . or ..; each component is at most 240 bytes. Fresh assignments are blank. See the ten event assignments for their names and Windows differences.

Test previews without saving. Clear removes the assignment, not the file; Save Changes saves the assignments. If saving is uncertain, use Reload Assignments to check saved values before further edits; do not blindly save again. Closing an editor with unsaved changes asks in-page whether to discard them or Cancel. Live playback pauses during editing and previews; old events are not replayed.

Upgrade an existing lowercase board

These steps support a current lowercase installation, including an existing Pop!_OS board. Keep a usable whole-board backup and use the same owner account and installation folder. Choose Stop BBS and wait for callers and maintenance to finish. Closing the browser does not close management. Run the installed command using your actual folder:

"$HOME/sfx/spitfire-x" --stop-management

The command refuses a running BBS, callers or active work and verifies that the installation lock is released. For a service-managed board it prints the exact administrator stop command. Once management has stopped, extract the new single TAR into a separate staging folder. From that new package, upgrade the EXISTING board:

tar -xzf spitfire-x-1.0.0b1-rc2-linux-x86_64-20261124-r1.tar.gz
cd spitfire-x-1.0.0b1-linux-x86_64
python3 install.py --prefix "$HOME/sfx" --upgrade

Substitute the real existing folder. Programs, web files and unchanged stock help are refreshed; board data, caller accounts, settings, messages, files, menus, artwork and Door/BotGate choices remain. Do not use a new empty folder or repeat initial BBS setup to update an established board. Preserve any retained transaction and follow the actual recovery result rather than deleting work to force an update.

After success, run the printed launcher command on the Linux desktop, check the version and saved settings, then deliberately Start BBS. The separate SSH route can reopen the same existing controls remotely.

These update controls apply only to an existing linux-lowercase-v1 board. They do not import or convert the old uppercase layout.

Linux updates refresh unchanged supplied files under docs and add missing guides. Edited or unrecognized copies are preserved. Keep a backup of your edits and compare preserved guides with the matching new package, since your copy may describe an older version.

Prepare a copied or moved board

Keep the complete SFX folder, including its key and private data. Under the intended Linux account, use the installed prepare-sfx in the copied folder to prepare that owned outer directory and open the controls. Then choose Prepare for This Computer in BBS Health Check or Backup & Restore, as offered.

Preparation keeps the board stopped and preserves its identity and contents. It does not repair every private file permission by making files readable to everyone. Use the intended account, avoid root and linked folders, and keep the complete folder together.

Moving a healthy complete folder or restoring a coherent older copy does not alone require FTN history recovery. If SFX reports that message ID history needs recovery, keep the BBS and any independently launched BinkD stopped and follow the guided FTN recovery steps.

Follow backup results

The built-in Linux Backup job captures the database and SFX's managed caller, Sysop-attention and Runtime journals before compression. Follow its actual result; accepted or queued is not completed. See Linux backup snapshots and failed backup details and retained work. Restore and stopped-board maintenance remain separate actions below.

Check or recover a stopped board

Tools & Maintenance > BBS Health Check reports findings and next steps; it does not repair the board. Leave the management app open while using the browser tool. A saved report is not an all-clear.

In Tools & Maintenance > Backup & Restore, Inspect Backup... starts Core Restore; Inspect File Contents... handles the file library separately. Stop BBS and finish active work first. Enter a verified managed SFX backup on the Linux computer. Keep its .sfx-owned marker and required companion backups together; an incremental point may need earlier archives. Copying an arbitrary ZIP into the folder does not make it a managed restore point.

Core Restore reviews and replaces the selected config/data/display/doors/logs/botgate/ftn core, retaining previous state. Live file-library contents and durable intake stay separate. Standard archive member names remain canonical; the verified Linux layout maps them to lowercase live paths. Final confirmation ends browser sessions: reopen through the launcher and read the result. Use preparation only if SFX asks. The BBS stays stopped.

Recover FTN History... is a separate stopped-board action in Backup & Restore. Keep the management app and browser open. SFX verifies the board and queued files, then offers Review FTN History Recovery... with UTC seconds, pending-file counts, separate held counts and the one-copy confirmation. Use it only for the reported history hold; it does not replace Core Restore or Prepare Copied Files. Read the full sequence and committed-report retry instructions.

Inspect File Contents... offers only areas included in that restore point, with none selected automatically. Select wanted areas and request their preview. Check every current destination and the missing, identical and conflict counts. The separate final Restore Missing Files confirmation creates only missing files. Identical files remain and conflicts are skipped; existing files are not replaced or deleted. Core settings and catalog identities stay unchanged. Read the finished counts.

The verified pre-restore safety backup records the current SFX version. In this build, that is 1.0.0b1; read the actual operation result before treating recovery as complete.

Selection and final confirmation are separate five-minute steps. Cancel in the final dialog declines the restore and leaves the preview open; Cancel Maintenance cancels the pending operation. If a reply is uncertain, read actual status before retrying. Keep failed or uncertain work for review; do not remove ownership markers, required archives or retained partial files to clear a hold.

Use File Manager Inspect/Reconcile or the offered preparation before serving restored files. Existing bytes alone do not mean a file is cataloged and ready. Prepare Copied Files... matches file records to copied or restored files; missing or changed files stay unresolved. Keep failed work and logs, and check the actual result before another attempt.
