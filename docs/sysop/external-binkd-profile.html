External BinkD supported profile (v1.0.0b1 test build)

This is the supported profile grammar for the helper included in the 1.0.0b1 test packages, not a complete stock BinkD manual or a runnable configuration. Read External BinkD setup guide for setup limits.

In this guide

  • Text format
  • Required network declarations
  • Remote links
  • Required shared receive folders
  • Required listener
  • Optional single-value lines
  • Paths and generated files
  • Review before use

Text format

Use lowercase directive names exactly as shown. Put one directive on each line. Separate words with spaces or tabs; double quotes can surround a value containing spaces. There are no backslash escapes or multiline values. A # starts a comment only at a word boundary; it cannot occur inside a value. Backslashes, embedded double quotes and control characters are not accepted inside values. Empty values are not accepted.

The profile is limited to 49,152 bytes. Each word is limited to 512 bytes; there may be at most 12 words on a line. Additional limits below also apply.

All UPPERCASE names and <angle-bracket> values below are placeholders. Do not save these examples as a deployment profile. Supply real configuration privately, with credentials agreed with your link's Sysop.

Required network declarations

Windows:

domain DOMAIN FTN/External/code/Outbound DEFAULT_ZONE

Fresh Linux:

domain DOMAIN ftn/external/code/outbound DEFAULT_ZONE

DOMAIN is the FTN domain name used by addresses below. "code" is the lowercase SFX network code, not a second spelling of the domain. DEFAULT_ZONE is an integer from 1 to 65535. Windows paths use the exact FTN/External/ prefix and /Outbound suffix; fresh Linux uses ftn/external/ and /outbound. Preserve address/domain/password values and the real spelling of the stock BinkD executable; this layout rule is for SFX-owned paths. Declare at least one domain; up to 64 are accepted. Domain names and network codes must each be unique without regard to case and must pass SFX's FTN-code validation.

address ZONE:NET/NODE.POINT@DOMAIN

Declare at least one local FTN address for every domain. Use a valid FTN address with an explicit declared domain; the point portion can be omitted for a node address. Up to 64 local address declarations are accepted.

The one shared profile can contain multiple domain and address lines. Each network still needs its matching SFX configuration. A profile declaration alone does not create that network or prove delivery.

Remote links

node ZONE:NET/NODE.POINT@DOMAIN HOST PASSWORD FLAVOUR - -

The address must be valid and use a declared domain. Up to 512 unique remote node declarations are accepted. The final two literal hyphens are required; they leave stock per-node outbound/inbound box overrides unset. The normal form above needs no -nr flag.

HOST is a single explicit host value accepted by stock BinkD, optionally with its port. HOST cannot start with a hyphen. This helper does not accept host lists, wildcards or shell expressions. Spaces, tabs, #, semicolon, *, ?, comma, dollar sign and backtick are refused, in addition to the general text restrictions above.

PASSWORD is one session password, at most 128 bytes. Spaces, tabs, !, comma, #, semicolon, *, dollar sign, backtick and ? are refused, along with the general text restrictions. Password lists and separate incoming/outgoing password forms are not supported. A literal - means an unprotected node; that node is not recorded as a password-protected remote address.

FLAVOUR must be one of i, c, h or -. These are the accepted stock flavour tokens. The restricted profile does not expose an outbound box, and this guide does not claim the complete SFX outbound flavour matrix is tested.

The optional form is:

node ZONE:NET/NODE.POINT@DOMAIN -nr HOST PASSWORD FLAVOUR - -

Stock BinkD calls -nr "Not Reliable Link". It is a specific outbound protocol workaround, not a default or recommended setting. Ordinary explicit node lines work without it. Use it only for the particular stock BinkD connection problem it addresses; it does not replace authenticated routing.

Required shared receive folders

Include each of these lines exactly once:

Windows:

inbound FTN/External/Inbound/Secure
inbound-nonsecure FTN/External/Inbound/Nonsecure
temp-inbound FTN/External/Temp

Fresh Linux:

inbound ftn/external/inbound/secure
inbound-nonsecure ftn/external/inbound/nonsecure
temp-inbound ftn/external/temp

These are relative to the board root. Do not replace them with absolute paths, outside-board folders, backslashes or per-network inbound folders. The launcher prepares the shared directories and the generated receive hook.

Required listener

listen LISTEN_VALUE

Exactly one listen line is required. Supply a listener value accepted by your stock BinkD build for the intended address and port. The profile parser checks the directive and text shape, not full stock listener syntax or whether that address/port can be used. Choose the listener for your installation; this guide does not change firewall rules.

Optional single-value lines

Each may appear at most once:

sysname "YOUR BBS NAME"
location "YOUR LOCATION"
sysop "YOUR SYSOP NAME"
nodeinfo "YOUR NODE INFORMATION"
timeout SECONDS
connect-timeout SECONDS
maxservers COUNT
maxclients COUNT

Timeouts must be integers from 1 to 3600; a trailing s is accepted. Server and client counts must be integers from 1 to 64. Text values remain subject to the 512-byte word limit and the general quoting rules. Stock BinkD's own interpretation still applies. Omit optional lines unless you need them.

Paths and generated files

The manually supplied source profile must be under FTN/External on Windows or ftn/external on fresh Linux. Supported relative path segments use only ASCII letters, digits, dot, underscore and hyphen, separated by forward slashes. They cannot be empty, . or .., or end in a dot. Absolute paths, drive prefixes, spaces and backslashes are refused. The relative path is limited to 512 bytes. These restrictions do not require renaming a physical board-root folder merely because it contains spaces.

The helper creates a private frozen binkd.cfg under FTN/External/Runs on Windows or ftn/external/runs on Linux for each run. It adds loglevel 4, conlog 0, a private per-run binkd.log and the completed-file recorder hook. The log can contain a password sent during a failed login. Keep it private and out of the SFX log viewer, support reports and chat. Windows access is limited to the Sysop, SYSTEM and Administrators; Linux uses mode 0600. Do not add or replace log, loglevel, conlog or exec directives yourself. The source input is validated before these generated lines are added.

Every directive not listed as accepted above is refused. This includes include, defnode, separate password-file directives, arbitrary receive commands and additional stock options. Do not broaden the profile by editing the generated copy; its contents are bound to that run's records.

Review before use

Check network codes, domains, addresses and private link credentials against the intended SFX configuration. Prepare under the normal Sysop account with the private file permissions described in the setup guide. Preserve earlier run files while mail still refers to them. A successfully parsed profile is not proof of successful connections, correct routes or delivery.

SFXConfig saves the mailer choice and stock program path; it does not write this private source profile or manage a BinkD service. The setup guide gives the Windows and Linux navigation and matching helper placement.

Eligible SFX-managed processed originals can expire under existing safety checks. Raw receive copies, runs, indexes and handoff history are preserved separately without a new automatic cleanup process; allow for their disk use. Keep the source profile and pending run metadata with the whole board.
