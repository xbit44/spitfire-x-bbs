Maintain, back up and recover

Choose when built-in jobs run, keep verified backups and review recovery before changing a stopped board.

Scheduled Jobs

Open Tools & Maintenance > Scheduled Jobs to edit External Events. Choose New Event, enter a name, the full program or script path on the BBS host, and the working folder. Leave Arguments blank when the command takes none. Use the Months, Days of month, and Days of week pickers to choose Any or specific entries. Choose a timing mode before saving.

New events start enabled. To suspend a saved event, clear Enabled and save. The saved schedule stays available when you enable it again, and any active run can finish.

All three calendar filters must match. A fixed time runs once on each matching day. For runs per day, 24 runs means the top of each hour. Create separate events for different exact times. Next scheduled run uses the BBS time zone. A skipped clock time in spring has no run and a repeated time in fall runs once.

For Door maintenance, select Take all nodes offline for this event and enter how long to wait for callers and Doors to finish. End calls at the scheduled time caps calling time at the event's deadline. Caller admission resumes after the command exits or if the wait limit is reached before the command starts. Write your script so it waits for the work it starts. Windows batch files can call other programs from the same script.

Use the two startup choices to run on each BBS start or to catch up once on a missed run. External Events run under the BBS Runtime account. On Windows in Desktop mode, a console event starts minimized on the taskbar under its event name. Restore the window if the script needs input. The Windows Events tab shows active event names and elapsed time. Review start, finish, and exit code in Events or Live Logs. Failures, skipped runs and optional long-run warnings appear in HeySysop.

Built-in jobs

Open Tools & Maintenance > Backup & Restore for the built-in schedules. In Linux SFXConfig, choose Open Backup Settings. Select Backup, Message Retention or Message Integrity before changing its schedule.

JobFresh schedulePurpose
BackupDisabled; daily at 02:00 when enabled.Create a managed backup using the saved folder and backup-retention setting.
Message RetentionEnabled; daily at 00:00.Apply public echo count/age limits and unread private-inbox age. Review message retention before reducing limits.
Message IntegrityEnabled; Sunday at 00:30.Check the message store and report findings. This does not repair data or run retention.

For each job, Enabled is On or Off, Hour is 0–23 and Minute is 0–59. Message Integrity also has a Day of week selector, Sunday through Saturday. Backup and Message Retention run daily and have no weekday choice. Existing saved schedules survive updates; the fresh defaults above do not replace your choices.

Choose Save Schedule on Windows or Save for the selected Linux job. Saving recalculates future scheduling without starting a job or restarting the BBS. Missed runs are skipped after a restart; jobs do not overlap or retry automatically. Check the displayed next eligible run after changing time or the BBS time zone.

Run Now is a separate action. Message Retention and Message Integrity require the BBS to be running; Run Now does not start it or disconnect callers. A queued result is not a completed result. Read the job's status, history and Events or logs. If the request's outcome is unknown, inspect that run before clicking again.

Message jobs report committed batches, public messages removed, unread recipient entries expired and applicable integrity holds. Partial, failed and interrupted results remain distinct. Earlier batches may already have committed. A fresh complete clean integrity check can release applicable holds; it does not automatically retry retention.

Backup folder and retention

These settings are under the built-in Backup schedule in Backup & Restore and apply to manual and scheduled backups.

SettingAllowed value and defaultWhen it applies
Backup destinationBlank uses Backup/Scheduled on Windows or backup/scheduled on Linux, beneath this SFX installation. Otherwise use an absolute local folder on the BBS computer, at most 2,048 UTF-8 bytes. For example, D:\SFXBackups on Windows or /home/bbs/sfx-backups on Linux.Future backups use the saved destination. A running backup keeps its original folder. Existing archives are not moved.
Verified managed archives retained1–365; fresh default 10. This is the number of verified managed backup archives to retain, not days. Zero and Unlimited are not accepted.Stop the BBS and finish active jobs before changing it. Saving the number does not itself delete archives.

The destination must pass the BBS account's access and privacy checks. Linux custom folders must be private and owned by that account. Do not enter a relative folder, a drive root, a network share or a trailing separator. Linux paths cannot contain empty, . or .. components. Windows paths use a drive letter and backslashes; wildcard characters, reserved device names, BIN components, tildes and components ending in a space or dot are refused. A rejected folder is not silently replaced with another destination.

On Windows, Browse... helps select the destination. On Linux, enter the path on the Linux server, even when you are using a Windows browser. If a copied board still has a path from another computer, correct it deliberately and check the next backup's actual destination. Saved destination and retention values survive normal updates.

Create and verify a backup

Linux SFXConfig: Choose the archive and recovery task, then follow its inspection, review and confirmation controls. This page has no ordinary settings save that performs a restore. Read the actual scope and stopped-board requirements. See editing and save results.

Open Backup & Restore. On Windows, choose Run Backup Now. A running BBS owns the requested backup, so closing Configuration does not cancel it; follow Events for the outcome. The stopped-board path reports its completed archive and verification result directly. Linux also offers the Backup job's Run Now control.

A core backup and a file-library content backup have different purposes. Core Restore does not restore protected programs or live file-library contents. File-area contents are included only for areas configured with Back up contents; that setting starts Off. An older or core-only restore point may contain no file-area contents.

On Windows, select a restore point and choose Verify; Refresh reloads the inventory. Check the displayed status and details, not just the archive name. Preserve managed backup markers and any required companion archives together. On Linux, keep the .sfx-owned marker; an incremental restore point may depend on earlier archives. An arbitrary ZIP copied into the backup folder is not a verified managed restore point.

New built-in manual/scheduled backups record the creating SFX version on both Windows and Linux. Existing archives retain their original metadata.

Linux backup snapshots

For a built-in manual or scheduled Linux backup, SFX briefly coordinates the database and its caller, Sysop-attention and Runtime journals. It finishes any caller entry already being published or refuses the capture. During that pause it makes checked copies of the database and the existing active and managed rotated files in the live logs/callers.log, logs/heysysop.log and logs/sfxruntime.log families.

The journal writers resume before compression starts. The archive uses those captured copies; later journal entries and rotations belong to the running board. Other included files keep their normal change-detection checks. This is not a whole-computer snapshot or a guarantee for files changed independently of SFX. Use the whole stopped-folder backup procedure for a separate complete-folder copy.

New Linux manual and scheduled backups record the version of SFX creating them: 1.0.0b2 in this build. Older archives keep their original recorded metadata. A version label does not replace archive verification.

Read a failed backup result

Read the complete result in Events and the logs. Archive streaming errors identify the member being processed and what failed; details can include expected and read byte counts or the archive writer's diagnostic. A changed source, a source read/hash failure and an archive write failure are different findings. Keep the detail exactly as reported.

A failed or cancelled capture can leave private work under Work on Windows or work on Linux for review. Preserve the reported paths and logs. Retained work is not a verified restore point; do not delete it, remove ownership markers or bypass checks to make another attempt proceed. Read actual status before retrying an uncertain operation.

A result explicitly saying Verified archive retained with retention incomplete means the archive was verified but the old-backup cleanup did not finish. Keep that verified archive and resolve the reported retention problem.

Back up the whole stopped folder

Use your ordinary backup or copy program to save the whole SFX folder with the BBS stopped.

  1. Let callers and active jobs finish, then stop the BBS and close the SFX programs. In Windows Service mode, stop the BBS service; closing Control Panel alone leaves it running. Stop any independently launched BinkD before copying the FTN files.
  2. Run the backup program with an account authorized to read the SFX folder. If you read through a network share or mapped drive, check which account the program uses.
  3. Include hidden files, nested folders and retained recovery folders. File areas, Door folders or backup folders outside the SFX folder need separate backup coverage.
  4. Save the backup outside the SFX folder. Read the program's result. Skipped or denied files mean the backup is incomplete.
  5. Try a restore into a new, separate folder. Compare the restored file list and file contents with the original, including hidden and nested files. Keep the working board untouched.

Keep the restored copy stopped while you check it and follow SFX's normal copied-board preparation. Keep every other copy using the same FTN addresses stopped before starting the replacement. Read the FTN copy and recovery precautions.

A mapped drive used by your other backup program does not change SFX's built-in Backup destination rules. That setting still requires a local folder on the BBS computer.

If access is refused

Keep the exact path and error from the backup log. Check the account used by the program and its read access through the share and to the files. Preserve custom permissions and retained recovery folders. Resolve the refused access before treating the backup as complete.

Windows permissions correction

The correction makes a normal Windows upgrade recheck retained recovery folders that SFX recognizes and establish read access for the board's Windows owner account. Existing ownership and custom permissions are preserved. This does not change unrelated folders or replace intentionally restricted access.

Restore core data

Fresh beta.11 Linux uses lowercase live paths, while the backup format retains canonical member names such as Config/SFX.conf, Data/SFX.DB and the standard journal/control names. SFX maps those known names during verified capture/restore; do not rename ZIP members. Linux Core Restore requires the matching Config/linux-layout.v1 schema marker in the archive. Older uppercase-layout archives without it are refused before staging; this is not a migration tool. Keep their original board and recovery tools separate.

Stop the BBS and finish active work first. On Windows, close Control Panel and keep Configuration open; select and verify the desired backup, then choose Restore Core.... SFX verifies the selected point and creates a verified pre-restore backup before replacing core owner data. Read the final result and any retained recovery paths.

On Linux, use Inspect Backup..., enter the managed archive path on the Linux computer and review the exact core to replace. Final confirmation ends browser sessions. Reopen through the launcher and read the result; the BBS remains stopped. See Linux recovery controls for the full sequence.

The pre-restore safety backup records the version of SFX creating it on both Windows and Linux. In this test build that is 1.0.0b2. The version is backup metadata, not a replacement for verification or a promise that an arbitrary older archive is compatible.

Core Restore keeps live Files and durable intake separate. Do not assume a restored catalog means every payload is present. Follow any requested FTN history recovery or file preparation, then check the board before starting it. If a result says live state changed, rollback failed or verification is incomplete, preserve the reported previous/failed state and logs instead of repeatedly restoring.

Recover FTN message ID history when asked

Use this action when SFX reports that message ID history needs recovery. A healthy complete-folder copy or a coherent older restore does not need this action merely because the computer changed or the backup is older. Use the normal copy/restore preparation first and read the actual result.

History recovery preserves existing message IDs, queued file bytes and known completed states. Separate held mail stays held. It is not a repair for damaged or incomplete board data, and it does not make it safe to run two copies with the same FTN addresses.

  1. Let callers and active work finish, then stop the BBS. On Windows, close Control Panel and open Configuration offline. In Service mode, stop the SFX service through its existing controls first. On Linux, keep the management app and browser controls open; the action closes the stopped board's database for maintenance itself.
  2. Stop any independently launched BinkD before doing history recovery. Keep every other copy using these FTN addresses stopped. SFX does not stop that separate mailer for you.
  3. Open Tools & Maintenance > Backup & Restore and choose Recover FTN History.... On Linux, wait for verification, then choose Review FTN History Recovery... when offered.
  4. Review Current UTC seconds, verified pending outbound/incoming file counts and the separate held-item counts. The queue does not have to be empty. Read the one-copy confirmation:

    This restored BBS will replace the previous copy. Any other copy using these FTN addresses is stopped.

    Choose Yes on Windows or Recover FTN History in the Linux review only when that statement is true.
  5. Read the actual result. FTN recovery complete. You can start the BBS. leaves the BBS stopped. Review any separate unresolved findings before deliberately starting it. If SFX says the history is healthy and recovery is not required, there is no history hold to clear.

Cancel or check an uncertain result

Declining the confirmation changes no history state. In the Linux browser, Cancel in the review dialog leaves the preview available; use Cancel Maintenance to cancel that pending preview. Its review expires after five minutes. Once you have confirmed recovery, closing the browser or asking to cancel is not a way to undo a committed result. Use Refresh Maintenance Status to read what happened before trying another action.

A committed recovery with a pending report

SFX writes a text report under Logs/FTN-Recovery-<operation>.log on Windows or logs/ftn-recovery-<operation>.log on Linux. If it reports committed but says the Logs report is pending, the recovery was already saved. With the BBS stopped, use Recover FTN History... again to retry that report export. It uses the saved recovery result; it does not repeat history recovery or clear another hold. If another history hold has appeared, SFX requires a new review and confirmation. Keep the original diagnostic if the report still cannot be written.

If verification refuses recovery, preserve the board, queued files and reported work. Missing or changed required files, invalid history or other integrity findings need their own review. Do not delete files or markers to force the action through. Use BBS Health Check and the exact diagnostic to find the next step. Recovery does not clear unrelated Held Mail or guarantee delivery by another board.

Restore missing file contents

  1. With the BBS stopped, choose Restore Contents... on Windows or Inspect File Contents... on Linux.
  2. Select a verified restore point and explicitly select the wanted file areas. No area is selected automatically. A point without selected-area content cannot supply those files.
  3. Review every current destination and the counts of missing files, identical files and conflicts. This preview does not restore files.
  4. Confirm the separate restore action only after checking those destinations. It creates missing files, leaves identical files alone and skips conflicting existing files. It does not overwrite or delete existing files, change core settings or replace catalog identities.
  5. Read the actual restored, identical and conflict counts. Use File Manager Inspect/Reconcile or the offered copied-file preparation before serving restored files.

Cancellation during selection or preview leaves the files unchanged. An incomplete execution needs review of the actual counts; do not assume every selected file was restored. See preparing a copied or moved Linux board when restoring onto another computer.

For Windows installation/path preparation after a move or restore, use the exact selected-folder Prepare guidance. A missing folder is not automatically a deleted board; uninstall and missing-folder recovery have separate confirmation and data-retention rules.

Compact a stopped database

Compact Stopped Database... is separate from message retention. It physically compacts the database while preserving logical contents and IDs; file size need not shrink. Stop the BBS first. The operation requires a verified prerequisite backup and refuses to proceed if that backup fails.

Read both the physical-commit and logical-verification results. Cancellation or an error after a physical commit is not the same as no change. Preserve the reported backup and recovery data if verification is unconfirmed. Compaction is not repair, secure erasure or an automatic nightly job.

In the Linux browser controls, closing the browser does not cancel compaction. Use Refresh Compaction Status to read the result, or Cancel Compaction to request cancellation. If Review Unconfirmed Request... appears, check the backup folder, preserved work and logs before acknowledging that review. The acknowledgement clears the browser warning; it does not repeat, cancel or mark the earlier operation successful.

BBS Health Check

Linux SFXConfig: Use the report controls after the stated stopped-board and idle checks. Opening this page runs nothing; the health report does not repair data or bypass recovery guards. See editing and save results.

With the BBS stopped, open Tools & Maintenance > BBS Health Check and choose Run BBS Health Check. This check reports problems and next steps; it does not repair or delete data. A dated text report is written to this board's Logs folder on Windows or logs folder on Linux when access permits.

Read every finding. Could not check is not a pass, and a saved report does not mean the board is healthy. On Windows, Cancel Check stops further checking while retaining findings already collected. If the report could not be saved, use the displayed findings and resolve the stated access or missing-file issue.

For a copied Linux board, Prepare for This Computer is a separate action when offered. It prepares the owned installation or copied-file records; it does not start the BBS or automatically repair an interrupted restore or compaction. Follow the copy and preparation steps.
