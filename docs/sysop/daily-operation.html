Windows startup

For a new board, finish the Control Panel's First-Run Setup before configuring the board in SFXConfig or accepting callers. Windows Setup opens the wizard automatically. If you chose Finish Later, reopen Control Panel using that board's shortcut or Bin\SFXControlPanel.exe. At completion, check the board name, initial System Sysop and Runtime readiness. See Windows first run.

On a fresh Desktop Mode board, Save Setup and Start BBS deliberately commits setup and starts configured caller listeners; Finish Later leaves initial setup pending. Check saved/readable settings separately from actual listener status: a bind/start failure can follow a successful save. Read the retained listener diagnostic and the actual startup result below. If SFXConfig reports that initial setup is needed, complete it in the same Control Panel and reopen SFXConfig. Verification, IPC and configuration-read diagnostics are different failures; preserve their reported details.

The Control Panel can open while SFX is still starting. Read its startup message and wait for the BBS and the listeners you use to report their actual running state. A visible window does not mean callers or FTN mail can connect yet. SFX completes required installation, database and connection-protection checks before accepting them.

While Runtime opens, the dots after SFX: opening Runtime — checking configuration and protection cycle from one to three and repeat. This startup indicator stops before the panel reports Ready, opens First-Run Setup or reports an error. It also stops when cancellation begins. A quick startup can finish before the dots cycle.

The Nodes table shows your configured nodes as Offline until SFX confirms their actual state. Wait for the listeners you use to report that they are running before connecting a caller.

On the Nodes tab, Disable All Nodes applies immediately when nobody is connected. With active callers, it asks for confirmation on the page and shows how many callers would be disconnected. Enable All Nodes enables every configured node, including nodes disabled individually. The Runtime stays running and SFX saves the node settings across a restart.

If startup fails, read the reported reason before trying again. Optional scanner and definition work can finish separately; uploads that require scanning still need a ready scanner. See ClamAV readiness and held uploads. Desktop Mode and Windows Service keep the separate hosting behavior below.

System > Runtime Behavior

Windows: BBS Hosting

Run BBS as chooses Desktop Mode or Windows Service (LocalSystem). A fresh installation uses Desktop Mode, with the registered service Disabled. Updates preserve the selected mode. Desktop Mode uses the Control Panel to run the BBS; Service mode lets the BBS continue when SFXConfig or the Control Panel is closed.

Start BBS when Windows starts applies in Service mode. Checked means automatic service startup; unchecked means Manual. Desktop Mode disables service startup. Service mode runs as LocalSystem, and Doors inherit that account's privileges; consider that when choosing the mode for your board.

Stop the BBS and close its stopped Control Panel before choosing Apply Hosting Settings. Review the mode and startup choice; Windows may ask for administrator approval. Applying the settings retains data and credentials and leaves the BBS stopped. When changing into Service mode, SFX offers a separate Start BBS now? choice. In Service mode, the page's Start BBS / Stop BBS control operates the service; in Desktop Mode, use the Control Panel.

Current mode, Service status and Current Windows startup show the actual saved/operating state. If hosting changed elsewhere or an outcome is uncertain, use Reload Hosting Settings to reconcile it before applying another change. A pending checkbox is not proof that Windows startup was changed. If the service registration is unavailable, use matching Setup Repair as the page directs.

Linux: Start BBS when Linux starts

This on/off choice starts off and is read when the installed Linux management service starts. Saving it does not start or stop the current BBS, register a service, or restart one. Opening the desktop launcher never starts the BBS for you. Updates preserve the saved choice.

Starting management with Linux and starting the BBS automatically are separate steps. Install the reviewed Linux service plan if you need boot startup and survival after logout, then use this checkbox to choose whether that service starts the BBS too. Read the page's service/startup result and use Refresh or Discard Changes to load a newer saved choice if another session changed it.

Change settings

Changing settings, saving your work and knowing when the new settings take effect.

Caller Idle Limits

If the BBS is running in Service mode, open the Control Panel before editing these limits. You can close the panel afterward without stopping the service.

Open SFXConfig > Connections > Caller Idle Limits, after Telnet & SSH and before External Client. Set “Caller AFK (minutes, 2-1440):” and “Login idle (seconds, 30-600):”.

Choose “Save Idle Settings” to save. If there is a problem, correct it and use “Retry Idle Settings” when available to try the settings connection again. Your edits stay in place, but Retry does not save them. Choose “Save Idle Settings”, then check the message showing what is saved and what is in use. Saved limits apply to new caller sessions. Sysops who have logged in are exempt from caller AFK. The login idle limit still applies before they log in.

Moving these settings does not change your saved values. BBS Hosting stays under System > Runtime Behavior. Editing idle limits is separate from starting or stopping the service.

Tools > Logging

Linux SFXConfig: Edit the separate Runtime, Callers and Attention log limits, then Save Changes. This does not perform the Control Panel’s Clear View action or mean that log files were deleted. See editing and save results.

Each of the three logs has its own active-file size and completed-archive count. A fresh board starts with 10 MiB and 10 archives for each log; updates keep your saved limits.

LogActive sizeCompleted archivesPurpose
Windows: SFXRuntime.log; Linux: sfxruntime.log1-100 MiB1-100Runtime and operational events.
Windows: CALLERS.LOG; Linux: callers.log1-100 MiB1-100Caller records.
Windows: HEYSYSOP.LOG; Linux: heysysop.log1-100 MiB1-100Items brought to the Sysop's attention.

Use whole numbers. A MiB is 1,048,576 bytes. For example, a size of 20 and an archive count of 5 sets that log's rotation size to 20 MiB and retains five completed archives in addition to its active file. These are file-size and file-count limits, not a number of days. Records are kept whole rather than split at the size boundary.

On Windows, choose Save Logging Settings; on Linux, save the page. A logging-only change can apply without restarting the BBS. Read Applied, Pending or Restart required if other settings are also pending. Completed archives beyond the retention limit are pruned oldest first, so lowering the count reduces retained history. Clearing the Control Panel's Live Logs display does not delete these files.

If Save is refused, check all six values; zero, fractional values and numbers above 100 are invalid. If the requested change is saved but not active, resolve the displayed pending condition before assuming that the new limits are in use.

Event sound assignments

Linux SFXConfig: Enter WAV paths on the Linux BBS computer. Test previews without saving; Save Changes keeps the assignments. This is separate from enabling sound playback in the browser Control Panel. See editing and save results.

On Windows, open Control Panel's BBS > Event Sounds.... On Linux, open System > Event Sounds in SFXConfig. Each of the ten assignments below holds a WAV path. Fresh assignments are blank (silent); updates preserve saved assignments.

AssignmentEvent
Telnet LoginA caller logs in through Telnet.
Telnet LogoutA Telnet caller logs out.
SSH LoginA caller logs in through SSH.
SSH LogoutAn SSH caller logs out.
Outbound RLogin EntryA caller enters an outbound RLogin connection.
Outbound RLogin ExitThe outbound RLogin connection ends.
Page SysopA caller pages the Sysop.
Security AlertA reported security event.
Operational/Error AlertA reported operating failure or maintenance problem.
Inbound BinkP ConnectionAn inbound BinkP connection event.

Use an absolute local .wav path, or blank for silence. The stored path limit is 768 UTF-8 bytes. Windows additionally limits the path to 259 characters and requires a local fixed drive, without links or junctions. Linux paths point to files on the BBS server, owned by its account; links and writable shared files are refused. For example, use C:\SFXSounds\login.wav on Windows or /home/bbs/sounds/login.wav on Linux.

Both platforms accept uncompressed PCM WAV: 8- or 16-bit, mono or stereo, 8–48 kHz, at most 30 seconds and 2 MiB. Changing a filename extension does not convert an unsupported audio file. Every nonblank assignment must validate before the set can be saved.

Use Test to preview an assignment without saving. Windows also offers file browsing. Clear removes the assignment from the draft and leaves the WAV file intact. Save the assignments to keep changes; no BBS restart is required. If the save result cannot be verified, reopen Event Sounds on Windows or use Reload Assignments on Linux before editing further.

On Linux, choose Enable Sounds in the Control Panel tab to hear new events on that browser computer. Only one tab receives the live stream. Playback pauses during editing/previews and stops when the controls are closed, you sign out or you switch to SFXConfig. Old events are not replayed. See browser sound controls.

Service sound note In Service mode, the Control Panel plays event sounds. Keep it open or minimized to hear them. Sounds do not play with the panel closed; that feature is set aside for later.
