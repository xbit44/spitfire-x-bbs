Customization & Displays

Make your BBS look like your BBS. Keep the working commands and access rules while you change the screens callers see.

This reference describes the existing display features in 1.0.0b2 on Windows and Linux. Start with a copied test board and keep your original artwork. Use the linked custom-display test sheet before putting a changed screen in front of callers.

Display folder and file choice

Put caller artwork in Display on Windows or display on Linux, directly under your SFX installation folder. .ANS files contain CP437 text and supported ANSI screen controls; .ASC files contain plain ASCII/CP437 without ANSI controls. Save BBS artwork in the intended character set: a UTF-8 file is not automatically converted to CP437. Fresh Linux uses lowercase SFX-generated filenames; a supplied custom artwork filename retains its actual spelling.

Names are matched without ASCII letter-case differences on both platforms. On Linux, keep just one spelling of each name: MAIN.ASC and main.asc together are ambiguous and are refused. Use ordinary files in the real Display folder, not symbolic links or Windows reparse points. On Linux, keep files owned by the account running SFX, with no group/world write permission or extra hard links. Preserve the installation's normal permissions.

For a menu with security variants, an ANSI caller at level 10 gets the first usable file in this order:

  1. MAIN10.ANS
  2. MAIN.ANS
  3. MAIN10.ASC
  4. MAIN.ASC

A plain caller tries MAIN10.ASC, then MAIN.ASC. ANSI artwork always takes priority over plain artwork within the ANSI choice, even when the plain file has the exact level. Missing, unreadable or invalid files are skipped in favor of the next candidate. Main caller menus fall back to generated menus if no custom candidate works; the file-group/area picker has the special limit below. An optional screen is normally skipped when no usable file exists; special refusal/chat fallbacks are described below.

Security suffixes are the caller's exact level, 1 through 999, without leading zeroes: MAIN10 and MAIN999. SFX does not search nearby levels or treat a suffix as a minimum. Artwork does not give a caller extra access or create commands. Keep its labels and keys in step with the configured commands. Generated menus handle lightbar positions; custom artwork does not define new lightbar hit areas.

Door menus and launch screens

DOOR is the root. A submenu uses DRnnn, where nnn is its zero-padded menu ID, 001 through 999. A Door's prelaunch screen uses DPnnn, with the zero-padded Door ID. These are IDs from the Door configuration, not the entry's visible position.

For menu ID 1, use DR001.ANS/DR001.ASC. For its exact level-10 artwork, use DR00110.ANS/DR00110.ASC. Door ID 7 uses DP007 and optionally DP00710. Each follows the same ANSI/exact-level/generic/plain fallback order as DOOR.

The hierarchy allows three displays in a path: root → category → subcategory. Artwork does not add another level or change the configured hierarchy. Use the stable numeric selections for custom Door menus. If a menu contains entries hidden from that caller, SFX uses a generated, caller-filtered menu instead of showing the authored menu. It checks access again when the caller enters a submenu or launches a Door.

DPnnn is tried for a Door selected from the Door menu before launch. Automatic logon/logoff Door events do not show it. Returning from a Door retains the launching menu path/page. See Door menus for configuration.

Door Bulletin pages use permanent Bulletin IDs: DB001.ANS/DB001.ASC through DB999.ANS/DB999.ASC, with normal exact-security variants such as DB00110.ANS. These are distinct from Door and menu IDs. Optional DBUL.ANS/DBUL.ASC appears as a compact header before the live generated index and its controls. Use the Door Bulletins setup guide for static pages, Door-generated scores and publication.

In this build, DRnnn and DPnnn artwork accepts the public display-code group below. Caller, Door and other full menu codes are not enabled for these two filename families; @DOORNAME@ is therefore not a usable DP launch-screen code.

BotGate and private chat files

These also live in Display on Windows or display on Linux, but use their own rules. They do not expand the @ codes or includes listed below.

FileUse and limits
bg-prelog.ansArtwork for the configured BotGate human challenge on an ANSI-capable connection. At most 16 KiB, with supported ordinary ANSI display controls. ## is the remaining-seconds field. An unusable file or plain connection gets the built-in challenge text. No general display-code expansion.
pchat.ansPrivate-chat frame when ANSI is active and the terminal is at least 80 columns by 24 rows. At most 32 KiB; frame occupies columns 1-79, rows 1-23. Leave columns 3-77 blank on rows 2, 4-19, 21 and 22 for title, conversation, input and controls. Only supported color and absolute cursor-position ANSI controls are allowed. Invalid/missing artwork gives the stock frame.
pchat.ascOptional private-chat heading on the plain/nonframed path, at most 32 KiB, 79 columns and 23 newline breaks, without control bytes other than CR/LF. Missing/invalid text is omitted; the built-in chat title, conversation and prompt remain. It is not an ANSI-frame fallback.
chat-emote.txtChat emote definitions. Current runtime reader accepts at most 32 KiB, up to 128 valid definitions. One line is NAME|NONE|text or NAME|TARGET|text. Names are 1-24 letters, case-insensitive, without duplicates; mode must be uppercase. Empty lines and lines starting # or ; are ignored. {caller} and {target} insert the names; a TARGET emote needs a target. Other display codes are literal.
WAVE|NONE|{caller} waves to everyone.
GREET|TARGET|{caller} greets {target}.

Keep emote text short and on one line. Control characters are removed and chat text is bounded; these definitions are not a script or a way to run a command.

Display codes and includes

Trusted menu and optional display files can insert values using codes such as @BBSNAME@. Code names ignore case. @@ produces one literal @; an ordinary email address or the standalone @ Sysop Utilities key stays literal. Unknown, incomplete, unavailable required or disallowed codes make that candidate unusable, so SFX tries its fallback. @PASSWORD@ and @BIRTHDATE@ are forbidden.

Which codes fit which screen?

The public group is BBSNAME SYSOP VERSION DATE TIME DATETIME NODE NODES TRANSPORT COLS ROWS. These are the only value codes enabled for general optional event screens, bulletin pages and DR/DP artwork. A value still needs to exist in that event's context; for example, an early or ending screen may not have node information. Start those screens with literal text and add only values you have checked.

WELCOME, NEWREG and NEWUSER also accept GRAPHICS. NEWUSER can accept caller fields when an authenticated context is explicitly supplied, but normal registration runs it before an account exists. Use public codes there, not caller-specific examples. NONODES.ASC, BotGate and the special chat files follow their literal/separate rules above.

The thirteen normal menu bases in the caller-menu table recognize all the value names below, subject to the live FGRP/FAREA context limit above. Optional values show empty when that menu has no matching caller, message, file, Door, chat or FTN context. A recognized value is not a promise that every menu has a current file or message selected.

Field widths and menu formats

@BBSNAME|L20@ makes a 20-byte field. Use L for left, R for right, C for center, or Z for numeric zero padding, with width 1-200. A value longer than its width is clipped: L keeps the left, R/Z the right, and C the middle. Width is bytes in the CP437 output, not a Unicode character count. Z requires an unsigned decimal value.

Normal menu files also accept the following named formats, for example @TIMELEFT:HMS@. Choose either a named format or a field width for one code; they cannot be combined.

  • TIMEON TIMELEFT UPTIME: :HMS, :MIN or :SHORT. Raw durations are seconds; MIN is whole minutes. An Unlimited value stays Unlimited.
  • FILESIZE: :AUTO, :B, :K, :M or :G. K/M/G use powers of 1024 and whole units.
  • DATE DATETIME ORGLOG LASTCALL MSGDATE FILEDATE: :SHORT keeps the canonical date/time form; :LONG spells out the month.
  • TIME: :12 or :24.

Optional event screens and DR/DP files use simpler formatting. SHORT, LONG, 12 and 24 leave their value text unchanged there. HMS/MIN require an unsigned number, as do the B/K/M/G/AUTO size conversions. Use plain public values on these screens unless you have checked the exact output; the normal menu's date/clock conversion does not carry over.

Screen and paging controls

@CLS@ clears the display; @BEEP@ requests a caller bell; @PAUSE@ asks for acknowledgment. @PROMPTOFF@/@PROMPT@ turn automatic paging off/on, and @NOABORT@/@ABORTON@ disable/enable caller abort of the display. A client may silence bells. These controls do not run a shell or menu command. A noninteractive disconnect/refusal can omit or refuse interactive controls.

Reuse a header or footer

@INCLUDE:HEADER.ASC@ inserts another file from the same Display folder. Use a simple leaf filename made from letters, digits or underscores and an .ASC or .ANS extension. No path, subfolder, drive, wildcard or .. is allowed. Plain displays may include ASC only; ANSI displays may include ASC or ANS. Included text keeps the parent screen's code permissions. A missing, unsafe, invalid or recursive include makes the parent candidate unusable.

@CLS@
Welcome to @BBSNAME@.
@INCLUDE:HEADER.ASC@
Your next menu keeps its normal commands.

File and output limits

A normal trusted display file is limited to 256 KiB. A resolved display allows at most 1 MiB of source including includes, 8 include levels, 64 include instances and 1 MiB of rendered output. The whole welcome sequence shares the aggregate/include/output limits. The smaller NONODES, BotGate and private-chat limits take precedence for those files.

Use ordinary screen colors and cursor movement in ANSI art. Unsupported terminal queries, unsafe controls, bad display codes or files that change while being read can make an asset unusable. Keep the generic ASC version useful so plain callers and ANSI fallbacks have a readable screen. SFX's program update keeps unrecognized/custom artwork; retain your own backup and use the test sheet to check an update on the spare board.

Edit the SF Newsletter

Choose @ Sysop Utilities > N Edit SF Newsletter to edit the whole newsletter file: Display/SFNWSLTR.ASC on Windows or display/sfnwsltr.asc on Linux. Ctrl-Z saves; Ctrl-A asks before discarding edits. Esc opens help and actions.

On a plain terminal, use /L to list lines, /E# to edit, /I# to insert, /D# to delete, /S to save and /A to cancel. Replace # with a line number, such as /E16.

The editor preserves tabs, spacing, line endings and a missing final newline. It does not sort entries or add dates. Use ASCII/CP437 text up to 256 KiB; ANSI controls are refused. If SFNWSLTR.ANS exists, the editor refuses to edit the ASC file and leaves both files unchanged to protect your artwork.

Setup does not seed a newsletter. A missing ASC file is created only when you explicitly save.

General > Displays & Menus

Linux SFXConfig: Edit the grouped caller colors and menu choices, then Save Changes. Menu preview and Door Commands remain separate tasks; a preview does not change a live caller screen. See editing and save results.

These board defaults control generated menu text, caller input and lightbar selection. They do not recolor your authored ANSI artwork or change plain ASCII files. Saved changes apply at the next menu redraw and to new logins; no BBS restart is needed for these settings alone.

On Windows, the Message Pipe Colors section places the private mail and NetMail switch beside the Pipe color style selector. Door Commands… is on the same row as Open Display Folder. See message pipe color modes for the code ranges and line behavior.

The starting values are for a fresh board. An existing board keeps its saved menu choices during a normal update. To try a different appearance, change the selection colors and preview an ANSI menu before saving. If Save refuses the colors, choose different base foreground/background colors. If artwork looks unchanged, check whether it supplies its own ANSI colors or you are viewing plain ASCII.

Preview without changing a caller session

The menu preview uses sample caller information. Select the menu, ANSI or ASCII, a security level from 1 to 999, and whether the sample is a Sysop. Refresh the preview to see what those choices can display. Windows starts with ANSI, level 10, Sysop authorization Off and Use matching artwork On. Clear Use matching artwork to inspect the built-in menu instead. Previewing does not save caller preferences, execute menu commands or grant anyone access. Windows shows a final 80-by-25 viewport; a long display can scroll within that view.

On Windows, Open Display Folder opens the board's Display folder for your ANSI or text editor. Refresh Preview after an artwork edit. Missing or unusable artwork falls back to built-in menus; normal Setup restores missing stock files. The preview's artwork switch changes only the preview. For registered Door hotkeys on primary menus, see Door Commands.
